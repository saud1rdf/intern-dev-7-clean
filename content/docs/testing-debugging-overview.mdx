# Testing & Debugging

Testing and debugging are not afterthoughts—they're integral to how professional developers write reliable software. The cost of fixing a bug increases exponentially the later it's discovered: $1 in development, $10 in testing, $100 in production, $1000+ after release.

This section teaches you how to build a comprehensive testing strategy, debug effectively when things go wrong, and implement observability so you can understand your application in production.

## Testing Philosophy

### Test Behavior, Not Implementation
```typescript
// ❌ BAD: Testing implementation details
expect(component.state.isOpen).toBe(true);
expect(wrapper.find('MyComponent').props().onClick).toHaveBeenCalled();

// ✅ GOOD: Testing user-visible behavior
expect(screen.getByRole('button', { name: /submit/i })).toBeEnabled();
await userEvent.click(screen.getByRole('button', { name: /submit/i }));
await waitFor(() => expect(screen.getByText(/success/i)).toBeInTheDocument());
```

### Testing Trophy (Modern Alternative)
For modern applications, consider the **Testing Trophy**:
- **Static Analysis** (TypeScript, ESLint) – Catches bugs before runtime
- **Unit Tests** – Pure functions, utilities, complex logic
- **Integration Tests** – Component trees, API routes, database
- **E2E Tests** – Critical paths only (login, checkout, onboarding)

## Debugging Methodology

### Scientific Debugging Process
1. **Reproduce** – Create minimal reproduction case
2. **Isolate** – Narrow down the scope (binary search)
3. **Hypothesize** – Form a theory about root cause
4. **Test** – Verify hypothesis with targeted experiment
5. **Fix** – Apply minimal, correct fix
6. **Verify** – Confirm fix works, add regression test
7. **Reflect** – Why did this happen? How to prevent?

### Common Debugging Tools

| Tool | Best For |
|------|----------|
| **Console.log / Debugger** | Quick inspection, simple flows |

## Structured Logging

### Why Structured Logs?
```javascript
// ❌ UNSTRUCTURED - Hard to search, parse, alert
console.log('User 123 logged in from Chrome on Mac');
console.error('Database connection failed: ECONNREFUSED');

// ✅ STRUCTURED - Queryable, filterable, machine-readable
logger.info({ userId: 123, browser: 'Chrome', os: 'Mac' }, 'User logged in');
logger.error({ err: error, service: 'database', operation: 'connect' }, 'Connection failed');
```

### Log Levels
| Level | Use Case |
|-------|----------|
| `trace` | Detailed flow debugging (very verbose) |
| `debug` | Development debugging information |
| `info` | General operational events |
| `warn` | Potential issues, deprecated usage |
| `error` | Handled errors, failed operations |
| `fatal` | Unrecoverable, process will exit |

## Error Handling Strategy

### Error Classification
```typescript
// Operational errors – Expected, handle gracefully
class OperationalError extends Error {
  constructor(public readonly code: string, message: string, public readonly statusCode = 400) {
    super(message);
    this.name = 'OperationalError';
  }
}

// Programmer errors – Bugs, crash and alert
class ProgrammerError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'ProgrammerError';
  }
}

// Usage
if (!user) throw new OperationalError('USER_NOT_FOUND', 'User does not exist', 404);
if (typeof user.id !== 'string') throw new ProgrammerError('User ID must be string');
```

### Async Error Handling Pattern
```typescript
// Wrapper for consistent error handling
async function safeAsync<T>(promise: Promise<T>): Promise<[T | null, Error | null]> {
  try {
    const data = await promise;
    return [data, null];
  } catch (error) {
    return [null, error instanceof Error ? error : new Error(String(error))];
  }
}

// Usage
const [user, error] = await safeAsync(fetchUser(id));
if (error) {
  if (error instanceof OperationalError) {
    return res.status(error.statusCode).json({ error: error.code });
  }
  logger.error({ err: error }, 'Unexpected error fetching user');
  return res.status(500).json({ error: 'INTERNAL_ERROR' });
}
```
