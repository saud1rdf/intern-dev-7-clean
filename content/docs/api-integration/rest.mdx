# REST API Integration & Defensive Validation

## Overview & The Why (لماذا هذا المفهوم حيوي؟)
In modern web architectures, API integrations are the critical point of contact between your frontend and the network. Frontend architectures that rely on loose types like `any` are vulnerable to **Schema Drift**—where backend changes break your UI without warning. Professional teams mitigate this by validating data at the network boundary using schemas (Zod).

## Key Concepts (المفاهيم الأساسية)
- **Defensive Client Patterns**: Validate payload structures before they reach your state managers.
- **Server API Proxy Routes**: Query third-party services via secure Server-Side Node.js proxies to hide credentials.
- **Exponential Backoff**: Implement retry logic to handle transient network failures gracefully.

## Production-Grade Code (الشيفرة البرمجية الإنتاجية)

### 1. Resilient API Fetch Wrapper (`lib/api-client.ts`)

```typescript
import { z } from 'zod';

export async function defensiveFetch<TSchema extends z.ZodTypeAny>(
  url: string,
  schema: TSchema,
  options: RequestInit = {}
): Promise<z.infer<TSchema>> {
  const response = await fetch(url, options);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  
  const rawData = await response.json();
  const validationResult = schema.safeParse(rawData);
  
  if (!validationResult.success) {
    console.error('[SCHEMA_DRIFT]', validationResult.error.format());
    throw new Error('Integrity validation failed');
  }
  return validationResult.data;
}
