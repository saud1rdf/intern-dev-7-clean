# REST API Integration & Defensive Validation

## Overview

APIs are the communication layer between frontend applications and external services. A reliable API integration must handle invalid data, security risks, network failures, and changing response structures.

Common problems include:

1. Schema changes from external APIs.
2. Exposing private API keys in frontend code.
3. Network failures and temporary service outages.

---

## Key Concepts

### Runtime Validation

TypeScript checks types during development, but types disappear when the application runs.

Runtime validation tools such as Zod verify that external data matches the expected structure.

### API Proxy Routes

Private API requests should pass through server-side routes instead of exposing sensitive credentials in the browser.

### HTTP Methods

Common REST operations:

- GET: Retrieve data.
- POST: Create new data.
- PUT: Replace existing data.
- PATCH: Update partial data.
- DELETE: Remove data.

# Production API Client

Example using Zod validation and retry handling:

```typescript
import { z } from "zod";

export class APIClientError extends Error {
  constructor(
    public status: number,
    public payload: unknown
  ) {
    super(`API request failed: ${status}`);
    this.name = "APIClientError";
  }
}

export async function defensiveFetch<T>(
  url: string,
  schema: z.ZodType<T>,
  retries = 3
): Promise<T> {

  let attempt = 0;

  while (attempt < retries) {
    try {
      const response = await fetch(url, {
        headers: {
          "Content-Type": "application/json",
        },
      });

      if (!response.ok) {
        throw new APIClientError(
          response.status,
          await response.text()
        );
      }

      const data = await response.json();

      return schema.parse(data);

    } catch (error) {

      attempt++;

      if (attempt >= retries) {
        throw error;
      }

      await new Promise(resolve =>
        setTimeout(resolve, 1000 * attempt)
      );
    }
  }

  throw new Error("Request failed");
}

Example server-side validation:

import { NextRequest, NextResponse } from "next/server";
import { z } from "zod";

const userSchema = z.object({
  name: z.string(),
  email: z.string().email(),
});


export async function GET(request: NextRequest) {

  try {

    const users = [
      {
        name: "Alice",
        email: "alice@example.com",
      },
    ];

    const validatedUsers = z
      .array(userSchema)
      .parse(users);


    return NextResponse.json({
      success: true,
      data: validatedUsers,
    });


  } catch (error) {

    if (error instanceof z.ZodError) {

      return NextResponse.json(
        {
          success: false,
          message: "Invalid response format",
        },
        {
          status: 400,
        }
      );
    }


    return NextResponse.json(
      {
        success: false,
        message: "Server error",
      },
      {
        status: 500,
      }
    );
  }
}

Best Practices
Never use any for API responses.
Validate external data before using it.
Keep API keys on the server.
Always define request headers.
Handle network failures gracefully.
