## Introduction

Postman is a powerful API development platform that simplifies every stage of the API lifecycle. Originally a Chrome extension, Postman has evolved into a comprehensive tool for building, testing, documenting, and monitoring APIs. It provides an intuitive graphical interface for making HTTP requests, organizing API workflows, and collaborating with team members.

Understanding Postman is essential for API developers and testers because it dramatically accelerates the development and testing process. Instead of writing code to test endpoints, you can interact with APIs through a user-friendly interface. Postman also generates documentation automatically, creates automated test suites, and enables team collaboration through shared workspaces and collections.

## When to Use Postman

Postman is valuable in multiple stages of API development and integration.

### API Exploration and Learning

When learning a new API or exploring unfamiliar endpoints, Postman's interface allows you to quickly make requests and see responses without writing any code. This is invaluable for understanding API behavior and debugging integration issues.

### Manual Testing and Debugging

Before writing automated tests, developers use Postman to manually verify API functionality. The ability to easily modify headers, request bodies, and authentication makes troubleshooting straightforward.

### Documentation Generation

Postman automatically generates beautiful, interactive documentation from your collections. This documentation includes code snippets in multiple languages and can be published or shared with API consumers.

### Automated Testing

Postman supports writing test scripts using JavaScript that run with each request. These tests can validate response status codes, response body content, and response times.

## Key Concepts

### Creating Requests

Postman allows you to create and send HTTP requests to any API endpoint.

```javascript
// GET Request
// URL: https://jsonplaceholder.typicode.com/users
// Headers: Accept: application/json

// POST Request
// URL: https://jsonplaceholder.typicode.com/users
// Headers: Content-Type: application/json
// Body:
{
  "name": "John Doe",
  "email": "john@example.com",
  "username": "johndoe"
}

// PUT Request (Complete update)
// URL: https://jsonplaceholder.typicode.com/users/1
// Body:
{
  "id": 1,
  "name": "Updated Name",
  "email": "updated@example.com",
  "username": "updatedusername"
}

// PATCH Request (Partial update)
// URL: https://jsonplaceholder.typicode.com/users/1
// Body:
{
  "name": "Patched Name"
}

// DELETE Request
// URL: https://jsonplaceholder.typicode.com/users/1
```

### Request Parameters

Postman provides multiple ways to send data with requests.

```javascript
// URL Parameters (Query params)
// https://api.example.com/users?page=2&limit=10&sort=name

// Path Variables
// URL: https://api.example.com/users/{{userId}}/posts/{{postId}}

// Headers
// Authorization: Bearer {{accessToken}}
// Content-Type: application/json
// X-Custom-Header: value

// Request Body - Raw JSON
{
  "name": "Test User",
  "email": "test@example.com",
  "settings": {
    "theme": "dark",
    "notifications": true
  }
}

// Request Body - Form URL Encoded
// name=John%20Doe&email=john%40example.com

// Request Body - Multipart Form Data
// Used for file uploads
// Field: file (Select File)
// Field: description (text value)
```

### Authentication

Postman supports various authentication methods.

```javascript
// No Auth (Default)
// Simple API Key
// Headers: X-API-Key: your-api-key

// Bearer Token
// Type: Bearer Token
// Token: {{accessToken}}

// Basic Auth
// Username: {{username}}
// Password: {{password}}

// OAuth 2.0 - Authorization Code Flow
// Callback URL: https://www.postman.com/oauth2/callback
// Auth URL: https://auth.example.com/authorize
// Access Token URL: https://auth.example.com/token
// Client ID: {{clientId}}
// Client Secret: {{clientSecret}}
// Scope: read write
// State: random-string

// OAuth 2.0 - Client Credentials Flow
// Token URL: https://auth.example.com/token
// Client ID: {{clientId}}
// Client Secret: {{clientSecret}}
// Scope: api.read

// AWS Signature (for AWS APIs)
// AWS Region: us-east-1
// Service Name: execute-api
// Access Key: {{accessKey}}
// Secret Key: {{secretKey}}

// Digest Auth
// Username: {{username}}
// Password: {{password}}
```

### Pre-request Scripts

Scripts that run before the request is sent.

```javascript
// Set environment variable
pm.environment.set("variableName", "value");

// Get variable value
const apiKey = pm.environment.get("apiKey");

// Generate random data
const randomId = Math.floor(Math.random() * 1000);
pm.variables.set("randomId", randomId);

// Set header dynamically
const timestamp = Date.now().toString();
pm.request.headers.upsert({
  key: "X-Timestamp",
  value: timestamp
});

// Generate UUID
function generateUUID() {
  return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, function(c) {
    const r = Math.random() * 16 | 0;
    const v = c === 'x' ? r : (r & 0x3 | 0x8);
    return v.toString(16);
  });
}

pm.variables.set("uuid", generateUUID());

// Set random email
const email = `test+${generateUUID()}@example.com`;
pm.environment.set("testEmail", email);

// Parse JSON from environment
const config = JSON.parse(pm.environment.get("configJSON"));
pm.request.headers.upsert({
  key: "Authorization",
  value: `Bearer ${config.token}`
});
```

### Test Scripts

JavaScript tests that validate responses.

```javascript
// Status Code Tests
pm.test("Status code is 200", function() {
  pm.response.to.have.status(200);
});

pm.test("Status code is 201 Created", function() {
  pm.response.to.have.status(201);
});

pm.test("Status code is 404 Not Found", function() {
  pm.response.to.have.status(404);
});

pm.test("Successful response", function() {
  pm.response.to.be.success;
});

// Response Body Tests
pm.test("Response has user data", function() {
  const jsonData = pm.response.json();
  pm.expect(jsonData).to.have.property('data');
  pm.expect(jsonData.data).to.have.property('name');
});

pm.test("User name is correct", function() {
  const jsonData = pm.response.json();
  pm.expect(jsonData.data.name).to.eql('John Doe');
});

pm.test("Response is an array", function() {
  const jsonData = pm.response.json();
  pm.expect(jsonData).to.be.an('array');
});

pm.test("Array has expected length", function() {
  const jsonData = pm.response.json();
  pm.expect(jsonData).to.have.lengthOf(10);
});

// Response Time Test
pm.test("Response time is less than 500ms", function() {
  pm.expect(pm.response.responseTime).to.be.below(500);
});

// Header Tests
pm.test("Content-Type is application/json", function() {
  pm.response.headers.has("Content-Type");
  pm.expect(pm.response.headers.get("Content-Type")).to.include("application/json");
});

// Schema Validation
const schema = {
  type: "object",
  properties: {
    id: { type: "number" },
    name: { type: "string" },
    email: { type: "string" }
  },
  required: ["id", "name", "email"]
};

pm.test("Schema is valid", function() {
  const jsonData = pm.response.json();
  pm.expect(tv4.validate(jsonData, schema)).to.be.true;
});

// Save data from response to environment
const jsonData = pm.response.json();
pm.environment.set("userId", jsonData.data.id);
pm.environment.set("userEmail", jsonData.data.email);

// Chain requests based on response
if (pm.response.code === 201) {
  const location = pm.response.headers.get("Location");
  pm.environment.set("createdResourceUrl", location);
}
```

### Variables

Postman supports different scopes of variables.

```javascript
// Global Variables
pm.globals.set("globalVar", "value");
pm.globals.get("globalVar");

// Collection Variables
// Set in collection settings
pm.collectionVariables.get("collectionVar");

// Environment Variables
pm.environment.set("envVar", "value");
pm.environment.get("envVar");

// Local Variables (request scope)
pm.variables.get("localVar");

// Priority order:
// Local > Environment > Collection > Global

// Using variables in requests
// {{baseUrl}}/users/{{userId}}/posts/{{postId}}

// Variable interpolation in scripts
const baseUrl = pm.variables.get("baseUrl");
const userId = pm.variables.get("userId");
const url = `${baseUrl}/users/${userId}/posts`;

// Dynamic variables
// {{$guid}} - UUID
// {{$timestamp}} - Current timestamp
// {{$randomInt}} - Random integer
// {{$randomUUID}} - UUID v4
```

### Workflows with Collection Runner

Create sequences of requests that run in order.

```javascript
// Example workflow: User Registration Flow
// 1. POST /auth/register (creates user)
// 2. POST /auth/login (gets token)
// 3. GET /users/me (verifies user)
// 4. PUT /users/me (updates profile)
// 5. POST /posts (creates first post)
// 6. DELETE /auth/logout (logs out)

// Using pm.sendRequest for chaining
// In the test script of step 1:
pm.test("Register and login", function() {
  const jsonData = pm.response.json();
  pm.environment.set("userId", jsonData.id);
  pm.environment.set("userEmail", jsonData.email);
});

// In the pre-request script of step 2:
const email = pm.environment.get("userEmail");
const password = pm.environment.get("testPassword");

// Or using pm.sendRequest for programmatic chaining
const loginRequest = {
  url: pm.environment.get("baseUrl") + "/auth/login",
  method: "POST",
  header: {
    "Content-Type": "application/json"
  },
  body: {
    mode: "raw",
    raw: JSON.stringify({
      email: pm.environment.get("userEmail"),
      password: pm.environment.get("testPassword")
    })
  }
};

pm.sendRequest(loginRequest, function(err, response) {
  if (!err) {
    const jsonData = response.json();
    pm.environment.set("accessToken", jsonData.accessToken);
  }
});
```

## Common Mistakes

### Not Using Environment Variables

```javascript
// ❌ WRONG - Hardcoded values
pm.test("Test", function() {
  const response = pm.sendRequest("https://api.example.com/users/123");
});

// ✅ CORRECT - Use variables
pm.test("Test", function() {
  const baseUrl = pm.environment.get("baseUrl");
  const userId = pm.environment.get("userId");
  const response = pm.sendRequest(`${baseUrl}/users/${userId}`);
});
```

### Forgetting to Handle Authentication

```javascript
// ❌ WRONG - No auth header
pm.test("Test", function() {
  pm.response.to.have.status(200);
});

// ✅ CORRECT - Add auth header
pm.test("Test", function() {
  const token = pm.environment.get("accessToken");
  pm.request.headers.upsert({
    key: "Authorization",
    value: `Bearer ${token}`
  });
  pm.response.to.have.status(200);
});
```

### Not Cleaning Up Test Data

```javascript
// ❌ WRONG - Creating resources without cleanup
pm.test("Create product", function() {
  pm.response.to.have.status(201);
  const jsonData = pm.response.json();
  pm.environment.set("productId", jsonData.id);
  // No cleanup step!
// ✅ CORRECT - Include cleanup in collection
// Add a final request in the collection to delete test data
```
