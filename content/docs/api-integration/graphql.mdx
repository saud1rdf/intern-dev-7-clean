# GraphQL Integration with Apollo Client

## Overview

GraphQL allows clients to request exactly the data they need from a single API endpoint.

Unlike REST APIs, GraphQL avoids:

- Over-fetching unnecessary data.
- Under-fetching related resources.
- Multiple API requests for connected data.

However, GraphQL applications require careful handling of caching, validation, and performance.

---

## Key Concepts

### GraphQL Schema

A schema defines available data structures and operations.

Main operations:

- **Query**: Read data.
- **Mutation**: Modify data.
- **Subscription**: Receive real-time updates.

---

### Apollo InMemoryCache

Apollo Client stores fetched data locally and automatically updates UI components when data changes.

Using unique identifiers like:


id
__typename


allows Apollo to normalize and update cached records correctly.

---

### WebSocket Subscriptions

Subscriptions keep a persistent connection between client and server for real-time features such as:

- Notifications.
- Live dashboards.
- Chat applications.

# Production Apollo Client Setup

```typescript
import {
  ApolloClient,
  InMemoryCache,
  HttpLink,
  ApolloLink,
  from,
} from "@apollo/client";

import { onError } from "@apollo/client/link/error";


const httpLink = new HttpLink({
  uri: process.env.NEXT_PUBLIC_GRAPHQL_API_URL,
});


const errorLink = onError(({ graphQLErrors, networkError }) => {

  if (graphQLErrors) {
    graphQLErrors.forEach(error => {
      console.error(
        "GraphQL Error:",
        error.message
      );
    });
  }


  if (networkError) {
    console.error(
      "Network Error:",
      networkError.message
    );
  }

});


const authLink = new ApolloLink((operation, forward) => {

  const token =
    typeof window !== "undefined"
      ? localStorage.getItem("token")
      : null;


  operation.setContext({
    headers: {
      authorization: token
        ? `Bearer ${token}`
        : "",
    },
  });


  return forward(operation);
});


export const apolloClient =
  new ApolloClient({

    link: from([
      errorLink,
      authLink,
      httpLink,
    ]),

    cache: new InMemoryCache(),

  });
GraphQL Query Example
import { gql } from "@apollo/client";


export const GET_USERS = gql`

query GetUsers {

  users {

    id

    name

    email

  }

}

`;
Using GraphQL in React
"use client";

import {
  useQuery
} from "@apollo/client";


function UsersList() {

  const {
    data,
    loading,
    error
  } = useQuery(GET_USERS);


  if (loading) {
    return <p>Loading users...</p>;
  }


  if (error) {
    return <p>Error loading users</p>;
  }


  return (

    <ul>

      {data.users.map((user) => (

        <li key={user.id}>

          {user.name}

        </li>

      ))}

    </ul>

  );

}


export default UsersList;
GraphQL Best Practices
Always Request id and __typename

Apollo uses these fields for cache normalization.

Example:

query {
  user {
    id
    __typename
    name
  }
}
Prevent Query Depth Attacks

Limit deeply nested queries to protect server performance.

Example:

user {
  posts {
    author {
      posts {
        author
      }
    }
  }
}
Use Code Generation

Generate TypeScript types from GraphQL schemas instead of manually writing interfaces.

Benefits:

Fewer type errors.
Better autocomplete.
Safer refactoring.
