## Introduction

GraphQL is a query language and runtime for APIs that was developed by Facebook and open-sourced in 2015. Unlike REST, which exposes multiple endpoints for different resources, GraphQL provides a single endpoint where clients can specify exactly what data they need. This approach eliminates over-fetching and under-fetching of data, giving clients more flexibility and reducing the amount of data transferred over the network.

GraphQL introduces a type system that allows APIs to self-document their capabilities. Clients can query the schema to discover available types and fields, making it easier to explore and understand the API. The strongly-typed nature of GraphQL also enables powerful developer tools that provide autocomplete, type checking, and error highlighting.

Understanding GraphQL is valuable for modern API development because it addresses many pain points of REST APIs, particularly for complex applications with varying data requirements across different clients. While REST remains popular for simple APIs and public-facing services, GraphQL excels in scenarios where clients need flexibility and the backend domain is complex.

## When to Use GraphQL

GraphQL is particularly well-suited for certain types of applications and scenarios.

### Complex Data Requirements

When clients need different views of the same data (mobile vs. desktop, different features), GraphQL allows each client to request exactly what it needs without creating multiple API endpoints or over-fetching unnecessary data.

### Mobile Applications

Mobile apps often operate on limited bandwidth and need to minimize network requests. GraphQL's ability to fetch multiple resources in a single request and request only required fields is particularly valuable for mobile development.

### Rapid Product Development

When building products that evolve quickly, GraphQL's flexible query structure allows frontend teams to adapt to new requirements without waiting for backend changes.

### Aggregating Multiple Services

GraphQL can serve as an API gateway that aggregates data from multiple microservices into a single graph, presenting a unified interface to clients.

## Key Concepts

### Schema Definition

The GraphQL schema defines the structure of your API using the Schema Definition Language (SDL).

```graphql
# Scalar types: String, Int, Float, Boolean, ID

type User {
  id: ID!
  name: String!
  email: String!
  age: Int
  posts: [Post!]!
  createdAt: String!
  updatedAt: String!
}

type Post {
  id: ID!
  title: String!
  content: String!
  author: User!
  comments: [Comment!]!
  tags: [String!]!
  createdAt: String!
  updatedAt: String!
}

type Comment {
  id: ID!
  content: String!
  author: User!
  post: Post!
  createdAt: String!
}

# Input types for mutations
input CreateUserInput {
  name: String!
  email: String!
  age: Int
}

input UpdateUserInput {
  name: String
  email: String
  age: Int
}

input PostFilterInput {
  tag: String
  authorId: ID
  search: String
}

# Enum types
enum Role {
  ADMIN
  USER
  MODERATOR
}

# Union types
union SearchResult = User | Post | Comment

# Interface types
interface Node {
  id: ID!
}

type Story implements Node {
  id: ID!
  title: String!
  author: User!
}

# Query root type
type Query {
  # Basic queries
  user(id: ID!): User
  users(first: Int = 10, after: String): UserConnection!
  post(id: ID!): Post
  posts(
    filter: PostFilterInput
    first: Int = 10
    after: String
  ): PostConnection!
  me: User
  
  # Search
  search(query: String!): [SearchResult!]!
  
  # Node interface for relay pagination
  node(id: ID!): Node
}

# Mutation root type
type Mutation {
  # User mutations
  createUser(input: CreateUserInput!): User!
  updateUser(id: ID!, input: UpdateUserInput!): User!
  deleteUser(id: ID!): Boolean!
  
  # Post mutations
  createPost(title: String!, content: String!, authorId: ID!): Post!
  publishPost(id: ID!): Post!
  deletePost(id: ID!): Boolean!
  
  # Comment mutations
  createComment(content: String!, postId: ID!, authorId: ID!): Comment!
  deleteComment(id: ID!): Boolean!
}

# Subscription root type
type Subscription {
  postCreated: Post!
  commentAdded(postId: ID!): Comment!
  userUpdated: User!
}
```

### Queries

Queries fetch data from a GraphQL server with precise control over the response structure.

```graphql
# Simple query
query GetUser {
  user(id: "123") {
    id
    name
    email
  }
}

# Nested queries
query GetUserWithPosts {
  user(id: "123") {
    id
    name
    posts {
      id
      title
      createdAt
    }
  }
}

# Query with arguments and aliases
query GetUsers {
  admins: users(role: ADMIN) {
    id
    name
  }
  regularUsers: users(role: USER, first: 5) {
    id
    name
  }
}

# Query with fragments
query GetPostWithComments {
  post(id: "456") {
    id
    title
    ...PostFields
    comments {
      ...CommentFields
    }
  }
}

fragment PostFields on Post {
  content
  createdAt
  author {
    id
    name
  }
}

fragment CommentFields on Comment {
  id
  content
  createdAt
  author {
    id
    name
  }
}

# Query with variables
query GetPosts($first: Int, $after: String) {
  posts(first: $first, after: $after) {
    edges {
      node {
        id
        title
        author {
          name
        }
      }
      cursor
    }
    pageInfo {
      hasNextPage
      hasPreviousPage
      startCursor
      endCursor
    }
    totalCount
  }
}

# Query directives
query GetPosts($includeComments: Boolean!) {
  posts {
    id
    title
    ... @include(if: $includeComments) {
      comments {
        id
        content
      }
    }
  }
}
```

### Mutations

Mutations modify server-side data and return the updated state.

```graphql
# Basic mutation
mutation CreateUser {
  createUser(input: {
    name: "John Doe"
    email: "john@example.com"
    age: 30
  }) {
    id
    name
    email
  }
}

# Mutation with nested creation
mutation CreatePostWithAuthor {
  createUser(
    input: {
      name: "Jane Smith"
      email: "jane@example.com"
    }
  ) {
    id
    name
    posts {
      id
      title
    }
  }
}

# Multiple mutations in one request
mutation UpdateUserAndPost {
  updateUser(id: "123", input: { name: "John Updated" }) {
    id
    name
  }
  publishPost(id: "456") {
    id
    published
  }
}

# Mutation with variables
mutation CreatePost(
  $title: String!
  $content: String!
  $authorId: ID!
) {
  createPost(
    title: $title
    content: $content
    authorId: $authorId
  ) {
    id
    title
    author {
      id
      name
    }
  }
}

# Inline fragments for union types
mutation CreateSearchItem {
  createItem(input: $input) {
    ... on User {
      name
      email
    }
    ... on Post {
      title
      content
    }
    ... on Comment {
      content
      postId
    }
  }
}
```

### Subscriptions

Subscriptions establish real-time connections for push-based updates.

```graphql
# Subscription for new posts
subscription OnNewPost {
  postCreated {
    id
    title
    author {
      id
      name
    }
    createdAt
  }
}

# Subscription for comments on a specific post
subscription OnNewComment($postId: ID!) {
  commentAdded(postId: $postId) {
    id
    content
    author {
      id
      name
      avatar
    }
    createdAt
  }
}

# Multiple subscriptions
subscription PostActivity {
  postCreated {
    id
    title
  }
  postDeleted {
    id
  }
}
```

## Full Example: GraphQL Server Implementation

```typescript
// schema.ts - Complete GraphQL schema definition
import { gql } from 'graphql-tag';

export const typeDefs = gql`
  scalar DateTime
  scalar JSON

  type User implements Node {
    id: ID!
    name: String!
    email: String!
    role: Role!
    posts(filter: PostFilterInput, first: Int, after: String): PostConnection!
    comments(first: Int): [Comment!]!
    createdAt: DateTime!
    updatedAt: DateTime!
  }

  type Post implements Node {
    id: ID!
    title: String!
    content: String!
    published: Boolean!
    author: User!
    comments(first: Int, after: String): CommentConnection!
    tags: [String!]!
    createdAt: DateTime!
    updatedAt: DateTime!
  }

  type Comment implements Node {
    id: ID!
    content: String!
    author: User!
    post: Post!
    createdAt: DateTime!
  }

  type PostConnection {
    edges: [PostEdge!]!
    pageInfo: PageInfo!
    totalCount: Int!
  }

  type PostEdge {
    node: Post!
    cursor: String!
  }

  type CommentConnection {
    edges: [CommentEdge!]!
    pageInfo: PageInfo!
    totalCount: Int!
  }

  type CommentEdge {
    node: Comment!
    cursor: String!
  }

  type PageInfo {
    hasNextPage: Boolean!
    hasPreviousPage: Boolean!
    startCursor: String
    endCursor: String
  }

  input CreateUserInput {
    name: String!
    email: String!
    password: String!
    role: Role
  }

  input UpdateUserInput {
    name: String
    email: String
  }

  input PostFilterInput {
    published: Boolean
    tag: String
    authorId: ID
    search: String
  }

  input CreatePostInput {
    title: String!
    content: String!
    authorId: ID!
    tags: [String!]
  }

  input CreateCommentInput {
    content: String!
    postId: ID!
    authorId: ID!
  }

  enum Role {
    ADMIN
    USER
    MODERATOR
  }

  type Query {
    # User queries
    node(id: ID!): Node
    users(first: Int, after: String): UserConnection!
    user(id: ID!): User
    me: User

    # Post queries
    post(id: ID!): Post
    posts(
      filter: PostFilterInput
      first: Int
      after: String
    ): PostConnection!
    
    # Search
    search(query: String!): [SearchResult!]!
  }

  type Mutation {
    # User mutations
    createUser(input: CreateUserInput!): User!
    updateUser(id: ID!, input: UpdateUserInput!): User!
    deleteUser(id: ID!): Boolean!

    # Post mutations
    createPost(input: CreatePostInput!): Post!
    publishPost(id: ID!): Post!
    unpublishPost(id: ID!): Post!
    deletePost(id: ID!): Boolean!

    # Comment mutations
    createComment(input: CreateCommentInput!): Comment!
    deleteComment(id: ID!): Boolean!
  }

  type Subscription {
    postCreated: Post!
    postPublished(id: ID!): Post!
    commentAdded(postId: ID!): Comment!
    userUpdated: User!
  }

  union SearchResult = User | Post | Comment
  interface Node {
    id: ID!
  }
`;

// resolvers.ts - Resolver implementation
import { PubSub } from 'graphql-subscriptions';
import { prisma } from '@/lib/prisma';
import { authenticate } from '@/lib/auth';

const pubsub = new PubSub();

// Event types for subscriptions
const EVENTS = {
  POST_CREATED: 'POST_CREATED',
  POST_PUBLISHED: 'POST_PUBLISHED',
  COMMENT_ADDED: 'COMMENT_ADDED',
  USER_UPDATED: 'USER_UPDATED',
};

export const resolvers = {
  Query: {
    node: async (_: any, { id }: { id: string }) => {
      const user = await prisma.user.findUnique({ where: { id } });
      if (user) return user;

      const post = await prisma.post.findUnique({ where: { id } });
      if (post) return post;

      const comment = await prisma.comment.findUnique({ where: { id } });
      if (comment) return comment;

      return null;
    },

    users: async (_: any, { first = 10, after }: any) => {
      const cursor = after ? { id: after } : undefined;
      const users = await prisma.user.findMany({
        take: first + 1,
        cursor,
        orderBy: { createdAt: 'desc' },
      });

      const hasNextPage = users.length > first;
      const edges = hasNextPage ? users.slice(0, -1) : users;

      return {
        edges: edges.map(user => ({
          node: user,
          cursor: user.id,
        })),
        pageInfo: {
          hasNextPage,
          hasPreviousPage: !!after,
          startCursor: edges[0]?.id,
          endCursor: edges[edges.length - 1]?.id,
        },
        totalCount: await prisma.user.count(),
      };
    },

    user: async (_: any, { id }: { id: string }) => {
      return prisma.user.findUnique({ where: { id } });
    },

    me: async (_: any, __: any, context: any) => {
      const user = await authenticate(context);
      return prisma.user.findUnique({ where: { id: user.id } });
    },

    post: async (_: any, { id }: { id: string }) => {
      return prisma.post.findUnique({ where: { id } });
    },

    posts: async (_: any, { filter, first = 10, after }: any) => {
      const cursor = after ? { id: after } : undefined;
      
      const where = {
        ...(filter?.published !== undefined && { 
          published: filter.published 
        }),
        ...(filter?.tag && { 
          tags: { has: filter.tag } 
        }),
        ...(filter?.authorId && { 
          authorId: filter.authorId 
        }),
        ...(filter?.search && {
          OR: [
            { title: { contains: filter.search } },
            { content: { contains: filter.search } },
          ],
        }),
      };

      const posts = await prisma.post.findMany({
        where,
        take: first + 1,
        cursor,
        orderBy: { createdAt: 'desc' },
      });

      const hasNextPage = posts.length > first;
      const edges = hasNextPage ? posts.slice(0, -1) : posts;

      return {
        edges: edges.map(post => ({
          node: post,
          cursor: post.id,
        })),
        pageInfo: {
          hasNextPage,
          hasPreviousPage: !!after,
          startCursor: edges[0]?.id,
          endCursor: edges[edges.length - 1]?.id,
        },
        totalCount: await prisma.post.count({ where }),
      };
    },

    search: async (_: any, { query }: { query: string }) => {
      const [users, posts, comments] = await Promise.all([
        prisma.user.findMany({
          where: {
            OR: [
              { name: { contains: query } },
              { email: { contains: query } },
            ],
          },
          take: 5,
        }),
        prisma.post.findMany({
          where: {
            OR: [
              { title: { contains: query } },
              { content: { contains: query } },
            ],
          },
          take: 5,
        }),
        prisma.comment.findMany({
          where: {
            content: { contains: query },
          },
          take: 5,
        }),
      ]);

      return [...users, ...posts, ...comments];
    },
  },

  Mutation: {
    createUser: async (_: any, { input }: any) => {
      const existing = await prisma.user.findUnique({
        where: { email: input.email },
      });

      if (existing) {
        throw new Error('Email already in use');
      }

      const user = await prisma.user.create({
        data: input,
      });

      return user;
    },

    updateUser: async (_: any, { id, input }: any, context: any) => {
      const currentUser = await authenticate(context);

      if (currentUser.id !== id && currentUser.role !== 'ADMIN') {
        throw new Error('Not authorized');
      }

      const user = await prisma.user.update({
        where: { id },
        data: input,
      });

      pubsub.publish(EVENTS.USER_UPDATED, { userUpdated: user });
      return user;
    },

    deleteUser: async (_: any, { id }: any, context: any) => {
      await authenticate(context);
      await prisma.user.delete({ where: { id } });
      return true;
    },

    createPost: async (_: any, { input }: any, context: any) => {
      const user = await authenticate(context);

      const post = await prisma.post.create({
        data: {
          ...input,
          authorId: user.id,
        },
        include: { author: true },
      });

      pubsub.publish(EVENTS.POST_CREATED, { postCreated: post });
      return post;
    },

    publishPost: async (_: any, { id }: any, context: any) => {
      await authenticate(context);

      const post = await prisma.post.update({
        where: { id },
        data: { published: true },
        include: { author: true },
      });

      pubsub.publish(EVENTS.POST_PUBLISHED, { postPublished: post });
      return post;
    },

    createComment: async (_: any, { input }: any, context: any) => {
      const user = await authenticate(context);

      const comment = await prisma.comment.create({
        data: {
          ...input,
          authorId: user.id,
        },
        include: { author: true, post: true },
      });

      pubsub.publish(EVENTS.COMMENT_ADDED, { 
        commentAdded: { ...comment, postId: input.postId } 
      });

      return comment;
    },

    deleteComment: async (_: any, { id }: any, context: any) => {
      await authenticate(context);
      await prisma.comment.delete({ where: { id } });
      return true;
    },
  },

  Subscription: {
    postCreated: {
      subscribe: () => pubsub.asyncIterator([EVENTS.POST_CREATED]),
    },
    postPublished: {
      subscribe: (_: any, { id }: { id: string }) => {
        const filter = (payload: any) => payload.postPublished.id === id;
        return pubsub.asyncIterator([EVENTS.POST_PUBLISHED]).filter(filter);
      },
    },
    commentAdded: {
      subscribe: (_: any, { postId }: { postId: string }) => {
        const filter = (payload: any) => payload.commentAdded.postId === postId;
        return pubsub.asyncIterator([EVENTS.COMMENT_ADDED]).filter(filter);
      },
    },
    userUpdated: {
      subscribe: () => pubsub.asyncIterator([EVENTS.USER_UPDATED]),
    },
  },

  // Type resolvers
  User: {
    posts: async (parent: any, args: any) => {
      return prisma.post.findMany({
        where: { authorId: parent.id },
        orderBy: { createdAt: 'desc' },
        take: args.first || 10,
      });
    },
  },

  Post: {
    comments: async (parent: any, { first = 10, after }: any) => {
      const cursor = after ? { id: after } : undefined;
      
      const comments = await prisma.comment.findMany({
        where: { postId: parent.id },
        take: first + 1,
        cursor,
        orderBy: { createdAt: 'desc' },
      });

      const hasNextPage = comments.length > first;
      const edges = hasNextPage ? comments.slice(0, -1) : comments;

      return {
        edges: edges.map(comment => ({
          node: comment,
          cursor: comment.id,
        })),
        pageInfo: {
          hasNextPage,
          hasPreviousPage: !!after,
          startCursor: edges[0]?.id,
          endCursor: edges[edges.length - 1]?.id,
        },
        totalCount: await prisma.comment.count({ 
          where: { postId: parent.id } 
        }),
      };
    },
  },

  SearchResult: {
    __resolveType(obj: any) {
      if (obj.title !== undefined) return 'Post';
      if (obj.postId !== undefined) return 'Comment';
      return 'User';
    },
  },
};
```

## Common Mistakes

### Over-fetching in Resolvers

```typescript
// ❌ WRONG - Fetching everything in every resolver
const resolvers = {
  Query: {
    user: async (_, { id }) => {
      return prisma.user.findUnique({
        where: { id },
        include: { 
          posts: true,
          comments: true,
          followers: true,
          following: true,
        },
      });
    },
  },
};

// ✅ CORRECT - Only fetch what's requested
const resolvers = {
  Query: {
    user: async (_, { id }) => {
      return prisma.user.findUnique({ where: { id } });
    },
  },
  User: {
    posts: async (parent) => {
      return prisma.post.findMany({
        where: { authorId: parent.id },
      });
    },
  },
};
```

### N+1 Query Problem

```typescript
// ❌ WRONG - Separate query for each post's author
const resolvers = {
  Post: {
    author: async (parent) => {
      return prisma.user.findUnique({ where: { id: parent.authorId } });
    },
  },
};

// When querying posts, this causes N+1 queries

// ✅ CORRECT - Use DataLoader for batching
import DataLoader from 'dataloader';

const userLoader = new DataLoader(async (userIds: string[]) => {
  const users = await prisma.user.findMany({
    where: { id: { in: userIds } },
  });
  
  const userMap = new Map(users.map(user => [user.id, user]));
  return userIds.map(id => userMap.get(id) || null);
});

const resolvers = {
  Post: {
    author: async (parent) => {
      return userLoader.load(parent.authorId);
    },
  },
};
```
