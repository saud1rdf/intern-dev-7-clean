# GraphQL Integration with Apollo Client



## Overview & The Why (لماذا هذا المفهوم حيوي؟)

GraphQL permits clients to query and aggregate disparate systems through an unified semantic gateway. Unlike REST, which often suffers from over-fetching unnecessary fields or under-fetching related records, GraphQL specifies response expectations down to the individual attribute layer.



However, unchecked or unoptimized GraphQL setups introduce severe performance issues:

1. **Normalized Cache Drift**: If queries do not share unique record identifiers (`__typename` and `id`), duplicate database rows yield conflicting client-side views.

2. **Server Overhead (N+1 Queries)**: Traversing un-cached nested structures under heavy relational loads can freeze production transactional tables.

3. **Loss of Compile Safe Types**: Failing to tie client-side query documents (AST) to code generation steps allows front-end variables to mismatch server schemas without compiler warnings.



---



## Key Concepts (المفاهيم الأساسية)



- **Unified Schema Gateway**: Merging disjointed microservice layers into cohesive semantic models, allowing clients to traverse properties within a single request.

- **Normalized InMemoryCache**: Keying elements unique to their entity signatures, facilitating instant updates across views whenever mutation calls execute.

- **Link Processing Pipeline**: Directing queries through configurable middleware layers before sending payloads to network hosts.

- **WebSocket Subscriptions**: Running long-lived connection tunnels alongside HTTP pipes to stream messages asynchronously.

### 1. Robust Apollo Client Configuration with Resilient Error Interceptor (`lib/apollo-client.ts`)

This setup aggregates link chains to inject authorization keys, catch network transport dropouts, and intercept GraphQL-specific schema errors gracefully:



```typescript

import { ApolloClient, InMemoryCache, HttpLink, ApolloLink, from } from '@apollo/client';

import { onError } from '@apollo/client/link/error';

import { z } from 'zod';



const isServer = typeof window === 'undefined';



// Validate system endpoint values safely prior to initialization

const configSchema = z.string().url();

const graphQLEndpoint = configSchema.parse(

  process.env.NEXT_PUBLIC_GRAPHQL_API_URL || 'http://localhost:3000/api/graphql'

);



// 1. Error Link Interceptor to handle unified API errors

const errorLink = onError(({ graphQLErrors, networkError }) => {

  if (graphQLErrors) {

    graphQLErrors.forEach(({ message, locations, path }) => {

      console.error(

        `[GraphQL_SCHEMA_ERROR] Message: ${message}, Path: ${path}`

      );

    });

  }

  if (networkError) {

    console.error(`[NETWORK_TRANSPORT_FAILURE] Failure details: ${networkError.message}`);

  }

});



// 2. Auth Link to inject enterprise context parameters

const authLink = new ApolloLink((operation, forward) => {

  const token = typeof window !== 'undefined' ? localStorage.getItem('token') : null;

  

  operation.setContext(({ headers = {} }) => ({

    headers: {

      ...headers,

      authorization: token ? `Bearer ${token}` : '',

    },

  }));

  

  return forward(operation);

});



const httpLink = new HttpLink({

  uri: graphQLEndpoint,

});



// 3. Centralized Apollo Client with optimized pagination cache policy

export const apolloClient = new ApolloClient({

  ssrMode: isServer,

  link: from([errorLink, authLink, httpLink]),

  cache: new InMemoryCache({

    typePolicies: {

      Query: {

        fields: {

          // Stable offset-limit pagination policy to append records safely

          users: {

            keyArgs: false,

            merge(existing = [], incoming) {

              return [...existing, ...incoming];

            },

          },

        },

      },

    },

  }),

});

Connecting GraphQL queries to components with complete error state monitoring and async loaders prevents unrendered views or white screens:

code

Tsx



'use client';



import { useQuery, gql } from '@apollo/client';

import { z } from 'zod';



export const GET_USERS_QUERY = gql`

  query GetActiveUsersList($limit: Int!, $offset: Int!) {

    users(limit: $limit, offset: $offset) {

      id

      fullName

      userEmail

      role

    }

  }

`;



// Validation schema for defensive client parsing

const userGqlNodeSchema = z.object({

  id: z.string(),

  fullName: z.string(),

  userEmail: z.string().email(),

  role: z.string(),

});



interface UserNode {

  id: string;

  fullName: string;

  userEmail: string;

  role: string;

}



interface QueryResultData {

  users: UserNode[];

}



interface QueryVariables {

  limit: number;

  offset: number;

}



export default function UsersList() {

  const { data, loading, error, fetchMore } = useQuery<QueryResultData, QueryVariables>(

    GET_USERS_QUERY,

    {

      variables: { limit: 10, offset: 0 },

      notifyOnNetworkStatusChange: true,

    }

  );



  if (loading && !data) {

    return <div role="status" className="animate-pulse">Retrieving records from Graph...</div>;

  }

  

  if (error) {

    return <div className="text-red-500 bg-red-50 p-4 rounded-lg">GraphQL Schema error: {error.message}</div>;

  }



  // Verify list format before rendering to prevent unexpected mapping faults

  const parseResult = z.array(userGqlNodeSchema).safeParse(data?.users);

  if (!parseResult.success && data?.users) {

    console.error('[GRAPHQL_SCHEMA_DRIFT] validation details failed:', parseResult.error.format());

    return <div className="text-red-500 bg-red-50 p-4 rounded-lg">Format signature is corrupted</div>;

  }



  const users = parseResult.data || [];



  return (

    <div className="space-y-4">

      <h3 className="text-lg font-bold text-slate-800 border-b pb-2">GraphQL Node View</h3>

      <ul className="divide-y divide-slate-100">

        {users.map((user) => (

          <li key={user.id} className="py-2.5 flex justify-between items-center text-sm font-sans">

            <div>

              <span className="font-extrabold block text-slate-800">{user.fullName}</span>

              <span className="text-xs text-slate-400 font-mono">{user.userEmail}</span>

            </div>

            <span className="text-xs font-bold uppercase bg-slate-100 text-slate-700 px-2.5 py-1 rounded">

              {user.role}

            </span>

          </li>

        ))}

      </ul>

      <button

        onClick={() =>

          fetchMore({

            variables: {

              offset: data?.users.length || 0,

            },

          })

        }

        className="text-xs font-bold text-indigo-600 hover:text-indigo-800 transition-colors"

      >

        Load More Records

      </button>

    </div>

  );

}

Best Practices (أفضل الممارسات التقنية)

	1	Always Request id and __typename: These properties are key to Apollo Client's normalization. Omitting them causes cache updates to fail silently.

	2	Defend against Query Depth Attacks: Malicious clients can design infinite loops of query depth (e.g. user { posts { author { posts { ... } } } }). Enforce query depth constraints at server gateways.

	3	Prefer Codegen over Loose Declarations: Auto-generate full TypeScript typings from your GraphQL files to catch type errors during compilation.
