# Git Basics & Branching Strategies

## Overview & The Why (لماذا هذا المفهوم حيوي؟)
In modern, high-availability enterprise environments, systems must track modifications with absolute mathematical certainty, auditability, and historical integrity. Version control is not merely a backup tool; it is the fundamental ledger of software state.

Without a rigorous and auditable history:
1. **Regression Profiling (git bisect)**: Isolating production bugs under load becomes a manual, slow search. Utilizing proper git mechanics permits binary searches on the commit graph to detect error commits in O(log N) iterations.
2. **Deterministic Releases**: Automations (Semantic Versioning) cannot auto-generate Changelogs or compute precise semver increments if commit messages are unstructured or loose (squashing is helpful but structured headers are essential).
3. **Reproducibility**: Compliance requirements mandate an untainted DAG (Directed Acyclic Graph) of commit signatures matching deployed container hashes.

---

## Key Concepts (المفاهيم الأساسية)

- **The Git Object Database**: In Git, all contents are stored as content-addressable objects under three main structural classes:
  - **Blobs**: Bare file content representation, excluding metadata or path hashes.
  - **Trees**: Directional directories mapping filenames to nested trees or direct blobs.
  - **Commits**: Cryptographically signed nodes identifying author stamps, timestamps, parent hashes, and pointers to root directory trees.
- **DAG (Directed Acyclic Graph)**: Branches are not isolated directories; they are loose references (pointer files containing a single SHA-1 hash) shifting along historical commit vertices on an immutable graph.
- **Trunk-Based Development**: Instead of maintaining highly concurrent, long-lived feature branches which yield extreme integration blockages (merge conflicts/friction), high-velocity teams rely on short-lived branches (1-2 days) merged frequently into the primary trunk (`main`), protected by feature flags to decouple releases from deployments.
- **Conventional Commits**: A structured commit format (`<type>(<scope>): <description>`) that serves as programmatic metadata.

## Production-Grade Code (الشيفرة البرمجية الإنتاجية)

### 1. Robust Three-way Merge conflict and Configuration (`.gitconfig`)
The industry standard is to configure three-way merges with `diff3`, which displays the common base ancestor alongside modified segments to let engineers resolve merges with perfect technical evidence.

```ini
# ~/.gitconfig or .git/config
[user]
    name = Distinguished Technical Writer
    email = documentation-lead@enterprise.com

[core]
    autocrlf = input
    editor = code --wait
    ignorecase = false

[merge]
    # Highlight original common ancestor content on conflict regions
    conflictstyle = diff3
    keepBackup = false

[pull]
    # Enforce rebase-first merges locally to deliver clean linear trees
    rebase = true

[alias]
    # Interactive, color-coded topological commit layout
    lg = log --graph --pretty=format:'%Cred%h%Creset -%C(yellow)%d%Creset %s %Cgreen(%cr) %C(bold blue)<%an>%Creset' --abbrev-commit --date=relative
    st = status -sb
    amend = commit --amend --no-edit

3. Automated Release Pipeline (.github/workflows/pipeline.yml)
Compile and parse commit history using automated GitHub Actions to deploy releases precisely matching SemVer coordinates:
code
Yaml

name: Continuous Release Process

on:
  push:
    branches:
      - main

jobs:
  release:
    name: Automatic Release compilation
    runs-on: ubuntu-latest
    permissions:
      contents: write
      issues: write
      pull-requests: write
    steps:
      - name: Checkout Code Node
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup Node Environment
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install Verified Dependencies
        run: npm ci

      - name: Verify Clean Build and Tests
        run: |
          npm run build
          npm run test -- --coverage

      - name: Run Semantic Release Gateway
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
        run: npx semantic-release

Git Command
Functional Enterprise Context
Failure Recovery Path
git checkout -b <name>
Synthesizes and switches focus to a new branch ref pointing to HEAD.
Delete draft ref local safely via git branch -D <name>.
git rebase origin/main
Relocates local commits on top of current main.
In event of conflict, abort cleanly via git rebase --abort.
git merge --no-ff <name>
Integrates a branch, forcing creation of a discrete merge commit.
Roll back full merge safely via git reset --hard HEAD~1.

Integrates exactly one commit node onto the current active branch.
Reset tracking branch using git cherry-pick --abort.

Best Practices (أفضل الممارسات التقنية)
	1	Never Rebase Shared History: Rewriting or squashing public remote history damages workflows and forces coworkers into manual branch re-alignment. Only rebase local branches.
	2	Use Atomic Commits: Keep every commit focused on a single logical change. Mixing formatting shifts, bugfixes, and code changes in one commit limits bisection capabilities.
	3	Leverage Force-with-lease: When uploading rebased features, use git push --force-with-lease rather than normal force. This checks that no coworkers have written intermediate updates to the remote.
