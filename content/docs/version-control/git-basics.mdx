# Git Basics & Branching Strategies

## Overview

Git is a distributed version control system that helps developers track changes, collaborate safely, and maintain a complete history of software development.

Version control allows teams to:

1. Track changes and identify when bugs were introduced.
2. Restore previous working versions.
3. Collaborate using branches and pull requests.
4. Automate releases and deployments.

---

## Key Concepts

### Git Object Database

Git stores data using three main object types:

- **Blob**: Stores file content.
- **Tree**: Stores directory structures and references to blobs.
- **Commit**: Stores snapshots with author information, timestamps, and parent commits.

### Branches

A branch is a movable pointer to a commit. Developers use branches to create isolated environments for new features or fixes.

Common workflow:


main
|
├── feature-login
|
└── bugfix-payment


### Trunk-Based Development

Modern teams often use short-lived branches that are merged frequently into the main branch.

Benefits:

- Smaller changes.
- Fewer merge conflicts.
- Faster delivery.

### Conventional Commits

A structured commit format:


<type>: <description>


Examples:


feat: add user authentication
fix: resolve login bug
docs: update API documentation

# Production Git Configuration

## Three-Way Merge Configuration

`.gitconfig`

```ini
[user]
    name = Developer
    email = developer@example.com

[core]
    editor = code --wait

[merge]
    conflictstyle = diff3

[pull]
    rebase = true

[alias]
    lg = log --graph --oneline --all
    st = status -sb
Commit Message Validation

Using commitlint helps enforce consistensages.

commitlint.config.json

{
  "extends": [
    "@commitlint/config-conventional"
  ],
  "rules": {
    "subject-empty": [
      2,
      "never"
    ],
    "subject-max-length": [
      2,
      "always",
      72
    ]
  }
}
GitHub Actions Release Pipeline

Example workflow:

.github/workflows/release.yml

name: Release Pipeline

on:
  push:
    branches:
      - main

jobs:
  release:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install Dependencies
        run: npm ci

      - name: Run Tests
        run: npm test

      - name: Build Project
        run: npm run build
Useful Git Commands
Command	Purpose
git checkout -b branch-name	Create a new branch
git rebase origin/main	Update branch history
git merge branch-name	Merge branches
git cherry-pick hash	Apply a specific commit
git status	Check current changes
git log	View commit history
Best Practices
Use Atomic Commits

Each commit should represent one logical change.

Good:

fix: resolve payment validation error

Bad:

changed css, fixed bugs, updated database
Avoid Rebasing Shared Branches

Do not rewrite history that other developers are already using.

Use Force With Lease

Prefer:

git push --force-with-lease

instead of:

git push --force

because it protects other developers' changes.
