## Introduction

Git branching is the foundation of modern collaborative development. Branches allow developers to work on multiple features, fixes, and experiments simultaneously without interfering with each other's code. A branch is essentially a movable pointer to a commit, with the main branch typically representing the production-ready state of your project.

Understanding branching is crucial because it enables parallel development, facilitates code review, and provides safety through isolation. Different teams use different branching strategies depending on their size, release frequency, and project requirements. Choosing and implementing the right branching strategy can significantly improve your team's productivity and code quality.

## When to Use Different Branching Strategies

Different project types and team sizes benefit from different branching approaches.

### Small Teams and Simple Projects

For small teams or simple projects, a basic feature branch workflow works well. Each feature gets its own branch, merged when complete. This is straightforward to understand and manage.

### Continuous Delivery

For projects that deploy frequently (multiple times per day or week), trunk-based development is often preferred. Developers merge small changes directly to the main branch, relying on feature flags and comprehensive testing.

### Large Teams and Release-Based Projects

For large teams or projects with scheduled releases, GitFlow or similar workflows provide structure. Multiple long-lived branches (develop, main, release branches) separate development, testing, and production code.

### Open Source Projects

Open source projects often use fork-and-branch workflows. Contributors fork the repository, create branches in their fork, and submit changes through pull requests.

## Key Concepts

### Branch Basics

```bash
# List all branches
git branch

# List remote branches
git branch -r

# List all branches (local and remote)
git branch -a

# Create a new branch
git branch feature/new-login

# Switch to a branch
git checkout feature/new-login
git switch feature/new-login

# Create and switch to a new branch
git checkout -b feature/user-dashboard
git switch -c feature/user-dashboard

# Rename current branch
git branch -m new-branch-name

# Delete a branch
git branch -d feature/completed-feature
git branch -D feature/unwanted-feature

# Delete remote branch
git push origin --delete feature/old-feature

# Compare branches
git diff main..feature/new-feature
git log main..feature/new-feature

# Merge a branch into current branch
git merge feature/new-feature

# Merge without fast-forward (creates merge commit)
git merge --no-ff feature/new-feature

# Abort a merge
git merge --abort
```

### Stashing Changes

```bash
# Save current changes (without committing)
git stash

# Save with a message
git stash save "WIP: working on login feature"

# List all stashes
git stash list

# Apply the most recent stash
git stash pop

# Apply a specific stash
git stash apply stash@{2}

# Keep staged changes after applying stash
git stash pop --index

# Create a branch from a stash
git stash branch feature/recover-stash

# Drop a stash
git stash drop stash@{0}

# Clear all stashes
git stash clear
```

### Rebasing

Rebase moves your branch's commits to a new base, creating a cleaner history.

```bash
# Rebase current branch onto main
git checkout feature/my-feature
git rebase main

# Continue rebase after resolving conflicts
git rebase --continue

# Abort rebase
git rebase --abort

# Skip a commit during rebase
git rebase --skip

# Interactive rebase (edit, reorder, squash commits)
git rebase -i HEAD~5

# Interactive rebase options:
# pick - keep commit as-is
# reword - edit commit message
# edit - stop at this commit to amend
# squash - combine with previous commit
# fixup - combine, discard commit message
# drop - remove commit

# Rebase onto a specific commit
git rebase --onto new-base old-base feature-branch

# Preserve merge commits during rebase
git rebase --preserve-merges main

# Pull with rebase instead of merge
git pull --rebase origin main
```

### Cherry-Picking

Apply specific commits from one branch to another.

```bash
# Cherry-pick a single commit
git cherry-pick <commit-hash>

# Cherry-pick multiple commits
git cherry-pick <commit-1> <commit-2> <commit-3>

# Cherry-pick a range of commits
git cherry-pick ^<start-commit> <end-commit>

# Cherry-pick without committing (stage changes)
git cherry-pick -n <commit-hash>

# Cherry-pick and edit commit message
git cherry-pick --edit <commit-hash>

# Cherry-pick from another branch
git cherry-pick main~3..main~1
```

## Branching Strategies

### Feature Branch Workflow

```bash
# Standard workflow for small teams
git checkout main
git pull origin main

# Create feature branch
git checkout -b feature/user-registration

# Work on feature, making regular commits
git add .
git commit -m "feat: add registration form"
git commit -m "feat: implement form validation"

# Sync with main periodically
git fetch origin
git rebase origin/main

# Push feature branch
git push -u origin feature/user-registration

# After review, merge via PR or command line
git checkout main
git pull origin main
git merge --no-ff feature/user-registration
git push origin main

# Clean up
git branch -d feature/user-registration
git push origin --delete feature/user-registration
```

### GitFlow Workflow

```bash
# Main branches:
# main (production) - tagged releases
# develop (integration) - next release

# Supporting branches:
# feature/* - new features
# release/* - release preparation
# hotfix/* - emergency fixes

# Start a feature branch
git checkout develop
git checkout -b feature/user-dashboard

# Finish feature
git checkout develop
git merge --no-ff feature/user-dashboard
git branch -d feature/user-dashboard

# Start release branch (when develop is ready)
git checkout -b release/1.0.0 develop

# Make release-related changes (version bump, docs)
# ... edit files ...
git commit -m "chore: bump version to 1.0.0"

# Finish release
git checkout main
git merge --no-ff release/1.0.0
git tag -a v1.0.0 -m "Release version 1.0.0"
git push origin main --tags

git checkout develop
git merge --no-ff release/1.0.0
git branch -d release/1.0.0

# Hotfix for critical bug
git checkout -b hotfix/security-patch main

# Make fix
git commit -m "fix: security vulnerability in auth"

# Finish hotfix
git checkout main
git merge --no-ff hotfix/security-patch
git tag -a v1.0.1 -m "Hotfix version 1.0.1"
git push origin main --tags

git checkout develop
git merge --no-ff hotfix/security-patch
git branch -d hotfix/security-patch
```

### Trunk-Based Development

```bash
# Main principle: Keep branches short-lived (1-2 days)
# Merge to main multiple times per day

# Daily workflow
git checkout main
git pull origin main

# Create short-lived feature branch
git checkout -b user-registration

# Make small changes, commit often
git add .
git commit -m "feat: add form markup"

# Sync frequently with main
git fetch origin
git rebase origin/main

# Push and merge quickly (within hours)
git push -u origin user-registration
# Create PR, get review, merge

# Feature flags allow incomplete features
if (features.newRegistration) {
  // new registration form
} else {
  // old form
}
```

### GitHub Flow

```bash
# Simple workflow for web applications

# 1. Main branch is always deployable
# 2. Create feature branch from main
git checkout main
git pull origin main
git checkout -b feature/awesome-feature

# 3. Make commits
git add .
git commit -m "feat: implement feature"

# 4. Push and create PR
git push -u origin feature/awesome-feature

# 5. After review and CI passing, merge
# 6. Deploy main branch immediately
```

## Full Example: Complex Feature with Multiple Contributors

```bash
# Team lead sets up feature coordination

# Create team feature branch (for integration testing)
git checkout develop
git pull origin develop
git checkout -b feature/team-project
git push -u origin feature/team-project

# Team member 1: Works on authentication
git checkout feature/team-project
git checkout -b feature/auth-service

# ... implements authentication ...
git add src/auth/
git commit -m "feat: add JWT authentication service"
git commit -m "feat: implement login/logout endpoints"

# Push and create PR to team feature branch
git push -u origin feature/auth-service
# ... PR review ...
# ... merge to feature/team-project ...

# Team member 2: Works on user dashboard
git checkout feature/team-project
git checkout -b feature/user-dashboard

# ... implements dashboard ...
git add src/dashboard/
git commit -m "feat: create dashboard layout"
git commit -m "feat: add user stats component"
git commit -m "feat: implement activity feed"

# Push and create PR
git push -u origin feature/user-dashboard
# ... PR review ...
# ... merge to feature/team-project ...

# Team member 3: Works on notifications
git checkout feature/team-project
git checkout -b feature/notifications

# Sync with team branch
git fetch origin
git merge origin/feature/team-project

# ... implements notifications ...
git add src/notifications/
git commit -m "feat: add notification service"
git commit -m "feat: implement email notifications"

# Push and create PR
git push -u origin feature/notifications
# ... PR review ...
# ... merge to feature/team-project ...

# Team lead: Integration and final merge
git checkout feature/team-project
git pull origin feature/team-project

# Run integration tests
npm run test:integration

# If all tests pass, merge to develop
git checkout develop
git merge --no-ff feature/team-project
git push origin develop

# Clean up
git branch -D feature/team-project
git push origin --delete feature/team-project
git branch -D feature/auth-service
git branch -D feature/user-dashboard
git branch -D feature/notifications
```

## Common Mistakes

### Long-Running Branches

```bash
# ❌ WRONG - Branch that lives for months
git checkout -b feature/epic-feature
# ... 3 months of work ...
# Massive merge conflicts guaranteed!

# ✅ CORRECT - Small, frequent merges
git checkout -b feature/login-form
# ... 1-2 days of work ...
# Merge and delete branch
```

### Not Syncing Before Merge

```bash
# ❌ WRONG - Merge without updating
git checkout main
git merge feature/stale-feature
# Huge conflicts because branch is out of date!

# ✅ CORRECT - Always sync first
git checkout main
git pull origin main
git checkout feature/stale-feature
git rebase origin/main
# Resolve conflicts if any
git checkout main
git merge feature/stale-feature
```

### Ignoring Merge Conflicts

```bash
# ❌ WRONG - Force pushing to skip conflict resolution
git rebase origin/main
# Conflicts appear
git rebase --skip  # Loses changes!

# ✅ CORRECT - Resolve conflicts properly
git rebase origin/main
# Edit conflicted files
git add <resolved-files>
git rebase --continue
```

## Exercises

1. **Feature Branch Workflow**: Create a feature branch, make multiple commits, rebase on main, and merge using --no-ff.

2. **Conflict Resolution**: Create two branches with conflicting changes, merge them, and resolve the conflicts manually.

3. **Interactive Rebase**: Practice cleaning up commits with interactive rebase: squash, reword, and reorder.

4. **Team Branching Simulation**: Simulate a team workflow where multiple people work on the same feature branch with regular integration.
