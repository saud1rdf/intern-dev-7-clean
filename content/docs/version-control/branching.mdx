## Introduction

In enterprise environments, branching is the backbone of parallel development. How you branch determines how fast you can ship code and how often you get stuck in merge conflicts.

---

## 1. The Strategy: Trunk-Based Development

High-performing teams (like those at Google and Facebook) prefer **Trunk-Based Development** over complex GitFlow. It keeps branches short-lived (1-2 days) and forces frequent merges to `main`.

```bash
# Workflow for a developer
git checkout main
git pull origin main

# Create a short-lived branch
git checkout -b feat/add-search-bar

# Work, commit, and sync with main frequently
git add .
git commit -m "feat(search): add search input component"
git rebase origin/main 

# Push and merge to main immediately
git push -u origin feat/add-search-bar

Summary & Best Practices
Short-lived branches: Merge to main within 24-48 hours.

Rebase frequently: Stay synced with main to avoid massive "merge hell" later.

Feature Flags: Use feature flags to hide incomplete code in main rather than keeping long-lived branches.

2. Advanced Merge WorkflowWhen working in teams, you often need to coordinate between multiple features. Use this workflow to integrate work safely.Bash# Team lead sets up feature coordination

# Create team feature branch (for integration testing)
git checkout develop
git pull origin develop
git checkout -b feature/team-project
git push -u origin feature/team-project

# Team member: Works on authentication
git checkout feature/team-project
git checkout -b feature/auth-service

# ... implements authentication ...
git add src/auth/
git commit -m "feat: add JWT authentication service"
git push -u origin feature/auth-service

# Team lead: Integration and final merge
git checkout feature/team-project
git pull origin feature/team-project

# Run integration tests
npm run test:integration

# If all tests pass, merge to develop
git checkout develop
git merge --no-ff feature/team-project
git push origin develop
