# HTML5 Semantic Markup

## Introduction

HTML (HyperText Markup Language) is the foundational language of the World Wide Web. It provides the structural skeleton for every web page, defining the meaning and hierarchy of content that browsers render and assistive technologies interpret. First proposed by Tim Berners-Lee in 1989 and standardized by the W3C, HTML has evolved through multiple versions, each adding capabilities that transformed how we build for the web.

HTML5, the current living standard, introduced landmark features that elevated HTML from simple document markup to a full application platform. Semantic elements like `<article>`, `<section>`, `<nav>`, and `<aside>` replaced generic `<div>` containers, giving meaning to content structure. Native multimedia via `<video>` and `<audio>` eliminated the need for third-party plugins. The `<canvas>` element enabled client-side graphics, and new APIs brought offline storage, geolocation, and drag-and-drop to the browser.

Understanding HTML deeply is essential for every web developer. HTML is the layer upon which CSS styling and JavaScript interactivity are built. Even in modern component-based frameworks like React and Vue, developers must grasp HTML semantics to produce accessible, well-structured, and SEO-friendly applications. The principles of semantic markup, proper nesting, and accessibility are universal skills that apply across every technology stack.

## Key Concepts

### Document Structure and Boilerplate

Every HTML document follows a standard structure that tells the browser how to parse, render, and handle the page. This structure includes the `<!DOCTYPE html>` declaration, the `<html>` root element, a `<head>` section with metadata, and a `<body>` section with visible content.

A complete, production-ready boilerplate includes viewport meta tags for responsive design, a character encoding declaration, a meaningful page title, external stylesheet links, and properly structured semantic sections. This foundation ensures your pages are accessible, performant, and ready for modern browsers.

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <!-- Character encoding — always declare first -->
    <meta charset="UTF-8">

    <!-- Viewport meta — essential for responsive design on mobile -->
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <!-- Page description — used by search engines in results -->
    <meta name="description" content="A brief, compelling description of this page (150-160 characters)">

    <!-- Page title — shown in browser tabs and search results -->
    <title>Page Title — Site Name</title>

    <!-- Favicon -->
    <link rel="icon" href="/favicon.ico" sizes="48x48">

    <!-- Preconnect to external origins for performance -->
    <link rel="preconnect" href="https://fonts.googleapis.com">
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

    <!-- Stylesheet -->
    <link rel="stylesheet" href="/styles.css">

    <!-- Open Graph meta for social sharing (optional) -->
    <meta property="og:title" content="Page Title">
    <meta property="og:description" content="Description for social sharing">
    <meta property="og:image" content="/og-image.png">
  </head>
  <body>
    <!-- Skip link — allows keyboard users to bypass repetitive navigation -->
    <a href="#main-content" class="skip-link">Skip to main content</a>

    <!-- Site header with primary navigation -->
    <header class="site-header">
      <nav aria-label="Primary navigation">
        <ul>
          <li><a href="/">Home</a></li>
          <li><a href="/about">About</a></li>
          <li><a href="/contact">Contact</a></li>
        </ul>
      </nav>
    </header>

    <!-- Main content — only one per page -->
    <main id="main-content">
      <article>
        <h1>Main Heading</h1>
        <p>Paragraph content goes here.</p>
      </article>

      <aside aria-label="Related content">
        <h2>Related Content</h2>
        <p>Sidebar information.</p>
      </aside>
    </main>

    <!-- Site footer -->
    <footer class="site-footer">
      <p>&copy; 2026 Company Name. All rights reserved.</p>
    </footer>

    <!-- Scripts at end of body for faster initial rendering -->
    <script src="/app.js" defer></script>
  </body>
</html>
```

### Semantic Elements

HTML5 introduced a set of semantic elements that describe the purpose and role of content within a page. Using these elements correctly provides three major benefits: accessibility (screen readers can navigate by landmark regions), SEO (search engines understand content hierarchy), and maintainability (developers can immediately identify the role of each section).

Each semantic element carries inherent meaning. `<header>` represents introductory content or navigation aids. `<nav>` wraps navigation links. `<main>` contains the dominant content. `<article>` holds self-contained, independently distributable content. `<section>` groups related content under a thematic heading. `<aside>` contains tangentially related content. `<footer>` provides closing information for its nearest ancestor sectioning content.

```html
<!-- Site-wide header — typically contains logo and primary navigation -->
<header class="site-header">
  <a href="/" aria-label="Home">
    <img src="logo.svg" alt="Company Name" width="150" height="40">
  </a>
  <nav aria-label="Primary navigation">
    <ul>
      <li><a href="/" aria-current="page">Home</a></li>
      <li><a href="/products">Products</a></li>
      <li><a href="/about">About</a></li>
      <li><a href="/contact">Contact</a></li>
    </ul>
  </nav>
</header>

<!-- Main content area — one per page -->
<main id="main-content">
  <!-- Article: self-contained, independently meaningful content -->
  <article>
    <header>
      <h1>How to Structure HTML Documents</h1>
      <p>
        Published on <time datetime="2026-01-15">January 15, 2026</time>
        by <a href="/authors/jane">Jane Smith</a>
      </p>
    </header>

    <section aria-labelledby="section-intro">
      <h2 id="section-intro">Introduction</h2>
      <p>Understanding document structure is fundamental to web development.</p>
    </section>

    <section aria-labelledby="section-body">
      <h2 id="section-body">Core Concepts</h2>
      <p>Detailed explanation of semantic HTML elements and their usage.</p>
    </section>

    <footer>
      <p>Tags: <a href="/tags/html">HTML</a>, <a href="/tags/semantics">Semantics</a></p>
    </footer>
  </article>

  <!-- Section: thematic grouping under a shared topic -->
  <section aria-labelledby="related-section">
    <h2 id="related-section">Related Articles</h2>
    <ul>
      <li><a href="/articles/css-basics">CSS Basics</a></li>
      <li><a href="/articles/accessibility">Web Accessibility</a></li>
    </ul>
  </section>
</main>

<!-- Aside: tangentially related content -->
<aside aria-label="Author bio">
  <h3>About the Author</h3>
  <p>Jane Smith is a front-end developer with 8 years of experience.</p>
</aside>

<!-- Footer: closing content for the page or section -->
<footer class="site-footer">
  <nav aria-label="Footer navigation">
    <ul>
      <li><a href="/privacy">Privacy Policy</a></li>
      <li><a href="/terms">Terms of Service</a></li>
    </ul>
  </nav>
  <p>&copy; 2026 Company Name</p>
</footer>
```

### HTML Forms and Validation

HTML forms are the primary mechanism for collecting user input on the web. HTML5 introduced new input types (`email`, `url`, `date`, `range`, `color`, etc.) and built-in validation attributes (`required`, `pattern`, `min`, `max`, `minlength`, `maxlength`) that reduce the need for JavaScript validation.

Every form input must have an associated `<label>` element. Labels are critical for accessibility — they allow screen readers to announce the purpose of each input, and they make the entire label text clickable to focus or toggle the input. Use `fieldset` and `legend` to group related controls, and use `autocomplete` attributes to help browsers auto-fill forms correctly.

```html
<form action="/api/register" method="POST" novalidate>
  <!-- Fieldset groups related controls; legend provides a visible heading -->
  <fieldset>
    <legend>Personal Information</legend>

    <div class="form-group">
      <label for="full-name">Full Name <span aria-hidden="true">*</span></label>
      <input
        type="text"
        id="full-name"
        name="fullName"
        required
        minlength="2"
        maxlength="100"
        autocomplete="name"
        placeholder="e.g. Jane Smith"
      >
      <small class="form-hint" id="name-hint">Between 2 and 100 characters</small>
    </div>

    <div class="form-group">
      <label for="email">Email Address <span aria-hidden="true">*</span></label>
      <input
        type="email"
        id="email"
        name="email"
        required
        autocomplete="email"
        placeholder="jane@example.com"
        aria-describedby="email-hint"
      >
      <small class="form-hint" id="email-hint">We will never share your email</small>
    </div>

    <div class="form-group">
      <label for="phone">Phone Number</label>
      <input
        type="tel"
        id="phone"
        name="phone"
        pattern="[0-9]{3}-[0-9]{3}-[0-9]{4}"
        autocomplete="tel"
        placeholder="123-456-7890"
        aria-describedby="phone-hint"
      >
      <small class="form-hint" id="phone-hint">Format: 123-456-7890</small>
    </div>

    <div class="form-group">
      <label for="birthday">Date of Birth</label>
      <input
        type="date"
        id="birthday"
        name="birthday"
        autocomplete="bday"
        min="1900-01-01"
        max="2008-01-01"
      >
    </div>

    <div class="form-group">
      <label for="website">Website</label>
      <input
        type="url"
        id="website"
        name="website"
        autocomplete="url"
        placeholder="https://example.com"
      >
    </div>
  </fieldset>

  <fieldset>
    <legend>Preferences</legend>

    <div class="form-group">
      <label for="country">Country <span aria-hidden="true">*</span></label>
      <select id="country" name="country" required autocomplete="country">
        <option value="">Select a country</option>
        <option value="us">United States</option>
        <option value="ca">Canada</option>
        <option value="uk">United Kingdom</option>
        <option value="de">Germany</option>
        <option value="other">Other</option>
      </select>
    </div>

    <div class="form-group">
      <label for="bio">Short Bio</label>
      <textarea
        id="bio"
        name="bio"
        rows="4"
        maxlength="500"
        placeholder="Tell us a little about yourself..."
        aria-describedby="bio-count"
      ></textarea>
      <small class="form-hint" id="bio-count">0 / 500 characters</small>
    </div>

    <div class="form-group">
      <fieldset>
        <legend>Newsletter Frequency</legend>
        <div class="radio-group">
          <label>
            <input type="radio" name="newsletter" value="daily">
            Daily digest
          </label>
          <label>
            <input type="radio" name="newsletter" value="weekly" checked>
            Weekly summary
          </label>
          <label>
            <input type="radio" name="newsletter" value="none">
            No newsletters
          </label>
        </div>
      </fieldset>
    </div>

    <div class="form-group">
      <label>
        <input type="checkbox" name="terms" required>
        I agree to the <a href="/terms">Terms and Conditions</a>
```

### Tables for Data

HTML tables should be used exclusively for presenting tabular data — never for page layout. A well-structured table uses `<thead>`, `<tbody>`, and `<tfoot>` to group rows, `<th>` elements with `scope` attributes to identify header cells, and `<caption>` to provide a concise table description. These features are essential for screen reader users, who navigate tables cell by cell and rely on headers being correctly associated with data cells.

```html
<table>
  <caption>Monthly Revenue Report — Q1 2026</caption>
  <thead>
    <tr>
      <th scope="col">Month</th>
      <th scope="col">Revenue</th>
      <th scope="col">Expenses</th>
      <th scope="col">Profit</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">January</th>
      <td>$52,000</td>
      <td>$31,000</td>
      <td>$21,000</td>
    </tr>
    <tr>
      <th scope="row">February</th>
      <td>$58,500</td>
      <td>$33,200</td>
      <td>$25,300</td>
    </tr>
    <tr>
      <th scope="row">March</th>
      <td>$64,000</td>
      <td>$35,800</td>
      <td>$28,200</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row">Total</th>
      <td>$174,500</td>
      <td>$100,000</td>
      <td>$74,500</td>
    </tr>
  </tfoot>
</table>
```

### Multimedia and Responsive Images

HTML5 provides native support for embedding images, audio, and video without third-party plugins. The `<img>` element supports `srcset` and `sizes` attributes that allow browsers to select the most appropriate image based on viewport width and pixel density, significantly improving performance on mobile devices. The `loading="lazy"` attribute defers offscreen image loading, and explicit `width` and `height` attributes prevent layout shift (CLS).

The `<video>` and `<audio>` elements provide built-in playback controls. Including `<track>` elements with WebVTT captions ensures multimedia content is accessible to deaf and hard-of-hearing users.

```html
<!-- Responsive image with art direction and density switching -->
<img
  src="hero-800w.jpg"
  srcset="
    hero-400w.jpg   400w,
    hero-800w.jpg   800w,
    hero-1200w.jpg 1200w,
    hero-1600w.jpg 1600w
  "
  sizes="(max-width: 600px) 100vw, (max-width: 1024px) 80vw, 1200px"
  alt="Team collaboration around a large monitor showing code review"
  loading="lazy"
  width="800"
  height="450"
>

<!-- Art direction: different image crops for different viewports -->
<picture>
  <source media="(min-width: 1024px)" srcset="product-wide.jpg">
  <source media="(min-width: 640px)" srcset="product-medium.jpg">
  <img
    src="product-square.jpg"
    alt="Product name shown in use on a kitchen countertop"
    loading="lazy"
    width="640"
    height="480"
  >
</picture>

<!-- Audio player with multiple source formats for compatibility -->
<audio controls preload="metadata">
  <source src="episode-42.mp3" type="audio/mpeg">
  <source src="episode-42.ogg" type="audio/ogg">
  <p>Your browser does not support the audio element.
     <a href="episode-42.mp3">Download the episode</a>.
  </p>
</audio>

<!-- Video player with captions, poster image, and multiple sources -->
<video
  controls
  width="640"
  height="360"
  poster="tutorial-poster.jpg"
  preload="metadata"
>
  <source src="tutorial.mp4" type="video/mp4">
  <source src="tutorial.webm" type="video/webm">
  <track
    kind="captions"
    src="tutorial-en.vtt"
    srclang="en"
    label="English captions"
    default
  >
  <track
    kind="captions"
    src="tutorial-ar.vtt"
    srclang="ar"
    label="Arabic captions"
  >
  <p>Your browser does not support the video element.
     <a href="tutorial.mp4">Download the video</a>.
  </p>
</video>

<!-- Figure with caption for standalone media with a description -->
<figure>
  <img
    src="architecture-diagram.png"
    alt="System architecture diagram showing three microservices connected through an API gateway"
    loading="lazy"
    width="800"
    height="500"
  >
  <figcaption>
    Figure 1: Microservices architecture overview. The API gateway routes
    requests to the authentication, data processing, and notification services.
  </figcaption>
</figure>
```

### Accessibility (a11y)

Web accessibility ensures that your content can be used by everyone, including people who rely on screen readers, keyboard-only navigation, or other assistive technologies. HTML provides the foundation for accessible interfaces through semantic elements, ARIA (Accessible Rich Internet Applications) attributes, proper heading hierarchy, skip links, and focus management.

Key principles: every interactive element must be keyboard-operable, every image needs meaningful alternative text (or explicit empty alt for decorative images), form inputs must have associated labels, dynamic content updates must be announced to screen readers via live regions, and focus order must be logical and visible.

```html
<!-- Skip link — the first focusable element on the page -->
<a href="#main-content" class="skip-link">Skip to main content</a>

<!-- Decorative image — empty alt tells screen readers to ignore it -->
<img src="decorative-border.svg" alt="" role="presentation">

<!-- Meaningful image — descriptive alt text -->
<img
  src="chart-q4-revenue.png"
  alt="Bar chart showing Q4 revenue increased 35% from $120K to $162K quarter-over-quarter"
  width="600"
  height="400"
>

<!-- ARIA combobox for a custom autocomplete component -->
<div
  role="combobox"
  aria-expanded="false"
  aria-controls="suggestions-list"
  aria-label="Search for a programming language"
>
  <input
    type="text"
    aria-autocomplete="list"
    aria-controls="suggestions-list"
    aria-activedescendant=""
    id="language-search"
  >
  <ul id="suggestions-list" role="listbox">
    <li role="option" id="opt-js">JavaScript</li>
    <li role="option" id="opt-py">Python</li>
    <li role="option" id="opt-rs">Rust</li>
  </ul>
</div>

<!-- Live region — announces dynamic updates to screen readers -->
<div
  role="status"
  aria-live="polite"
  aria-atomic="true"
  id="form-status"
>
  <!-- Populated dynamically, e.g., "Form submitted successfully" -->
</div>

<!-- Alert — immediately announced, for urgent messages -->
<div role="alert" id="error-banner">
  <p>Please fix the following errors before submitting.</p>
</div>

<!-- Proper heading hierarchy — one h1, logical nesting -->
<main id="main-content">
  <h1>Web Development Fundamentals</h1>

  <section aria-labelledby="html-heading">
    <h2 id="html-heading">HTML Basics</h2>
    <p>HTML provides the structure for web pages.</p>

    <article>
      <h3>Semantic Elements</h3>
      <p>Using elements that describe their content improves accessibility.</p>

      <h4>When to Use Each Element</h4>
      <p>Each semantic element has a specific purpose and use case.</p>
    </article>
  </section>

  <section aria-labelledby="css-heading">
    <h2 id="css-heading">CSS Styling</h2>
    <p>CSS controls the visual presentation of HTML content.</p>
  </section>
</main>
```

## Common Pitfalls

### Using Divs for Everything

The most common anti-pattern in HTML is using `<div>` and `<span>` for every element, discarding the semantic meaning HTML5 provides. This harms accessibility (screen readers cannot identify page landmarks), hurts SEO (search engines cannot understand content hierarchy), and reduces maintainability (developers cannot visually distinguish a header from a sidebar from a footer without reading class names).

```html
<!-- Problem: non-semantic div soup — no meaning, no accessibility -->
<div class="header">
  <div class="nav">
    <div class="logo"></div>
    <div class="menu">
      <div class="item"><a href="/">Home</a></div>
      <div class="item"><a href="/about">About</a></div>
    </div>
  </div>
</div>
<div class="main-content">
  <div class="article">
    <div class="title"></div>
    <div class="body"></div>
  </div>
  <div class="sidebar"></div>
</div>
<div class="footer"></div>

<!-- Solution: semantic elements — meaningful, accessible, maintainable -->
<header>
  <nav aria-label="Primary navigation">
    <a href="/" aria-label="Home">
      <img src="logo.svg" alt="Company Name" width="120" height="40">
    </a>
    <ul>
      <li><a href="/">Home</a></li>
      <li><a href="/about">About</a></li>
    </ul>
  </nav>
</header>
<main>
  <article>
    <h1>Article Title</h1>
    <p>Article body content.</p>
  </article>
  <aside aria-label="Sidebar">
    <h2>Related Links</h2>
  </aside>
</main>
<footer>
  <p>&copy; 2026 Company Name</p>
</footer>
```

### Missing or Poor Alt Text

Images without alt text are invisible to screen readers. Placeholder text like `"image"` or `"photo"` provides no information. Descriptive alt text should convey the content or function of the image. Decorative images (purely visual, no informational content) should use an empty `alt=""` attribute to be ignored by assistive technologies.

```html
<!-- Problem: missing, empty, or placeholder alt text -->
<img src="team-photo.jpg" alt="image">
<img src="chart.png" alt="">
<img src="icon.svg">

<!-- Solution: descriptive alt for informational images, empty alt for decorative -->
<img
  src="team-photo.jpg"
  alt="Seven team members posing in the office lobby during the 2026 company retreat"
  width="800"
  height="450"
>
<img
  src="chart.png"
  alt="Line chart showing user growth from 2,000 in January to 8,500 in June 2026"
  width="600"
  height="400"
>
<img src="icon.svg" alt="" role="presentation" width="24" height="24">
```

### Breaking Heading Hierarchy

Headings (`<h1>` through `<h6>`) create an outline of your page that screen readers use for navigation. Skipping levels (e.g., jumping from `<h2>` to `<h4>`) or having multiple `<h1>` elements confuses both assistive technologies and search engine crawlers. Each page should have exactly one `<h1>`, and subsequent headings should descend in order without skipping levels.

```html
<!-- Problem: skipped heading levels and multiple h1 elements -->
<h1>Company Home Page</h1>
<h1>Welcome to Our Services</h1>
<h3>Web Development</h3>
  <h5>Frontend</h5>

<!-- Solution: one h1 per page, levels descending in order -->
<h1>Company Name — Web Development Services</h1>

<h2>Web Development</h2>
  <h3>Frontend Development</h3>
    <h4>React Applications</h4>
    <h4>Vue.js Applications</h4>
  <h3>Backend Development</h3>
    <h4>Node.js APIs</h4>
    <h4>Python Services</h4>

<h2>Design Services</h2>
  <h3>UI/UX Design</h3>
  <h3>Brand Identity</h3>
```

### Ignoring Form Labels

Every form input must have an associated `<label>` element. Without labels, screen readers cannot announce what each input is for, and sighted users lose the click-to-focus convenience. Using `placeholder` text as a substitute for labels is a common mistake — placeholders disappear when the user types and do not meet accessibility requirements.

```html
<!-- Problem: missing labels, placeholder used as label -->
<div>
  <input type="text" placeholder="Your name">
</div>
<div>
  <input type="email" placeholder="Email">
</div>

<!-- Solution: properly associated labels with for/id pairing -->
<div class="form-group">
  <label for="contact-name">Full Name <span aria-hidden="true">*</span></label>
  <input
    type="text"
    id="contact-name"
    name="name"
    required
    autocomplete="name"
    placeholder="e.g. Jane Smith"
  >
</div>
<div class="form-group">
  <label for="contact-email">Email Address <span aria-hidden="true">*</span></label>
  <input
    type="email"
    id="contact-email"
    name="email"
    required
    autocomplete="email"
    placeholder="jane@example.com"
  >
</div>
```

## Practical Tasks for Interns

### Task 1: Build a Personal Portfolio Page

Create a single-page personal portfolio using only HTML (no CSS or JavaScript yet). The page should demonstrate proper semantic structure, accessibility features, and correct heading hierarchy.

**What to build:**
- A complete HTML page with `<header>`, `<main>`, and `<footer>` landmarks
- A navigation bar with anchor links to page sections
- A hero section with your name and a brief introduction
- An "About Me" section with a short bio
- A "Projects" section with at least three project entries using `<article>` elements
- A "Contact" section with a simple form
- A skip link, proper heading hierarchy (one `<h1>`, descending `<h2>`/`<h3>`), and meaningful alt text on any images

**External resources:**
- [MDN: Getting Started with HTML](https://developer.mozilla.org/en-US/docs/Learn/HTML/Introduction_to_HTML/Getting_started)
- [web.dev: Learn HTML](https://web.dev/learn/html)
- [W3C HTML Validator](https://validator.w3.org/) — validate your finished page here

**Step-by-step local setup:**
1. Create a folder called `portfolio-task` on your desktop.
2. Inside it, create a single file called `index.html`.
3. Start with the full HTML boilerplate: `<!DOCTYPE html>`, `<html lang="en">`, `<head>` with `charset`, `viewport`, `title`, and `<body>`.
4. Add a skip link as the first element in `<body>`: `<a href="#main-content" class="skip-link">Skip to main content</a>`.
5. Create a `<header>` with your name in an `<h1>` and a `<nav>` with anchor links.
6. Create `<main id="main-content">` with `<section>` elements for About, Projects, and Contact.
7. In the Projects section, use `<article>` elements with `<h3>` headings and descriptive paragraphs.
8. In the Contact section, add a `<form>` with labeled `<input>` fields for name, email, and message.
9. Add a `<footer>` with copyright information.
10. Open `index.html` in your browser, then paste the source code into the [W3C Validator](https://validator.w3.org/) and fix any reported errors.

### Task 2: Create an Accessible Registration Form

Build a multi-section registration form that demonstrates all HTML5 input types, built-in validation attributes, proper label associations, fieldset groupings, and ARIA descriptions.

**What to build:**
- A form with at least two `<fieldset>` groups with `<legend>` headings
- Input types: `text`, `email`, `password`, `tel`, `date`, `url`, `select`, `textarea`, `radio`, `checkbox`, and `range`
- Each input must have a `<label>` with a matching `for`/`id` pair
- Validation attributes: `required`, `minlength`, `maxlength`, `pattern`, `min`, `max`
- `aria-describedby` on inputs with helper text or error message containers
- A submit button and a reset button

**External resources:**
- [MDN: Forms Guide](https://developer.mozilla.org/en-US/docs/Learn/Forms)
- [WebAIM: Form Accessibility](https://webaim.org/techniques/forms/controls)
- [HTML5 Doctor: Form Elements](http://html5doctor.com/)

**Step-by-step local setup:**
1. Create a folder called `form-task` on your desktop.
2. Inside it, create `index.html` and `styles.css` (link it in the `<head>`).
3. Start with the HTML boilerplate and add a `<main>` with an `<h1>` heading.
4. Create a `<form>` with `action` and `method` attributes (even if the endpoint is fictional for now).
5. Add the first `<fieldset>` with `<legend>Personal Details</legend>` and include name, email, password, and date of birth inputs, each with a `<label>`.
6. Add the second `<fieldset>` with `<legend>Preferences</legend>` and include a country dropdown, a textarea for a bio, radio buttons for a plan choice, and a terms checkbox.
7. Add validation attributes to every required input and pattern-based validation where appropriate.
8. Add `<small>` helper text below inputs that need format guidance, and connect it with `aria-describedby`.
9. Add submit and reset buttons at the bottom.
10. In `styles.css`, add a `.visually-hidden` utility class and style `.form-group` with spacing.
11. Open `index.html`, test tab-through navigation (Tab key), and verify every input is announced correctly by a screen reader or by Chrome's accessibility inspector.

### Task 3: Build a Responsive Data Dashboard with Tables

Create a page containing at least two data tables demonstrating proper table semantics, accessibility attributes, and responsive behavior.

**What to build:**
- Two `<table>` elements with `<caption>`, `<thead>`, `<tbody>`, and `<tfoot>`
- All `<th>` elements must have correct `scope="col"` or `scope="row"` attributes
- A "monthly sales" table and a "team performance" table
- A proper heading hierarchy connecting tables to their section headings
- Use CSS (basic inline or linked) to make tables horizontally scrollable on small screens using `overflow-x: auto` on a wrapper `<div>`

**External resources:**
- [MDN: HTML Tables](https://developer.mozilla.org/en-US/docs/Learn/HTML/Tables)
- [W3C: Tables Tutorial](https://www.w3.org/WAI/tutorials/tables/) — comprehensive accessibility guide

**Step-by-step local setup:**

3. Start with the HTML boilerplate and add a `<main>` with an `<h1>` heading.
4. Add a `<section>` with an `<h2>` heading and the first table (Monthly Sales Report) with all four table sections (`caption`, `thead`, `tbody`, `tfoot`).
5. Add a second `<section>` with an `<h2>` heading and the second table (Team Performance) with the same structure.
6. Ensure every `<th>` has the correct `scope` attribute.
7. In `styles.css`, wrap each table in a `<div class="table-wrapper">` with `overflow-x: auto; max-width: 100%;`.
8. Style `<caption>` with `caption-side: top; padding: 0.5rem; font-weight: 600;`.
9. Open `index.html` in your browser, resize the window to mobile width, and verify both tables scroll horizontally without breaking the layout.
10. Validate the page with the [W3C Validator](https://validator.w3.org/).

### Task 4: Create an Image Gallery with Lazy Loading

Build a page that displays a collection of images using semantic HTML, responsive image techniques, and native lazy loading.

**What to build:**
- A gallery page using a `<section>` with a heading and a list of `<figure>` elements
- Each `<figure>` must contain an `<img>` with a descriptive `alt` attribute and a `<figcaption>`
- All images must use `loading="lazy"` and explicit `width`/`height` attributes to prevent layout shift
- At least one `<picture>` element with multiple `<source>` elements for different viewports
- A decorative logo image using `alt=""` and `role="presentation"`

**External resources:**
- [web.dev: Lazy Loading](https://web.dev/articles/fast-lazy-loading)
- [MDN: Lazy Loading](https://developer.mozilla.org/en-US/docs/Web/Performance/Lazy_loading)
- [web.dev: Responsive Images](https://web.dev/learn/design/responsive-images/)

**Step-by-step local setup:**
1. Create a folder called `gallery-task` on your desktop.
2. Inside it, create `index.html` and `styles.css`.
3. Start with the HTML boilerplate and add a `<main>` with an `<h1>` heading.
4. Add a decorative `<img>` near the top with `alt=""` and `role="presentation"`.
5. Create a `<section>` with an `<h2>` heading for the gallery.
6. Add at least six `<figure>` elements, each containing an `<img>` and a `<figcaption>`. Use placeholder image services (e.g., `https://picsum.photos/800/600?random=1`) and set explicit `width="800"` and `height="600"` attributes.
7. Add `loading="lazy"` to every gallery image.
8. Create one `<picture>` element with `<source>` elements for `min-width: 1024px` and `min-width: 640px`, with a fallback `<img>`.
9. In `styles.css`, use CSS Grid to lay out the gallery: `display: grid; grid-template-columns: repeat(auto-fit, minmax(300px, 1fr)); gap: 1rem;`.
10. Style `<figcaption>` with padding, centered text, and a smaller font size.
11. Open `index.html`, open browser DevTools Network tab, and scroll slowly to verify images load lazily (you should see requests fire as images enter the viewport, not all at once).

### Task 5: Build a Documentation Page with Proper Semantics

Create a documentation-style page that demonstrates complex semantic structure, nested sections, code blocks, a table of contents, and proper heading hierarchy.

**What to build:**

- Each section should contain `<h3>` subsections and `<h4>` sub-subsections where appropriate
- Include `<pre><code>` blocks for code examples
- Add a sidebar `<nav>` with a table of contents using anchor links to each section heading
- Use `<dl>` (definition list) for a glossary or terminology section
- Use `<blockquote>` for an important note or quote

**External resources:**

**Step-by-step local setup:**

3. Start with the HTML boilerplate and add a `<main id="main-content">`.
4. Add an `<h1>` document title and a brief introductory `<p>`.
5. Create a two-column layout: a `<nav aria-label="Table of contents">` sidebar with anchor links, and the main `<article>` content area.
6. In the article, create at least four `<section>` elements, each with an `<h2>` heading and `id` matching the corresponding nav link.
7. Inside at least one section, add `<h3>` and `<h4>` subsections to create a three-level heading hierarchy.

11. In `styles.css`, style the layout with Flexbox (sidebar + main content), add a background to `<pre>` blocks, and style `<blockquote>` with a left border.
12. Verify heading hierarchy by running the page through a heading outline tool or by manually checking that no levels are skipped.
