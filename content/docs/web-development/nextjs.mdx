## Introduction

Next.js is a React framework developed by Vercel that provides structure, features, and optimizations for building production-ready web applications. Originally released in 2016, Next.js has evolved to become the de facto standard for React applications, offering a comprehensive solution for routing, rendering, data fetching, and deployment.

The framework addresses many of the challenges developers face when building React applications from scratch. It handles the complex configuration required for build tools like Webpack and Babel, provides intelligent file-based routing, and offers multiple rendering strategies to optimize performance and user experience.

Next.js 15 introduced significant changes including the App Router, Server Components, and improved streaming capabilities. These features enable developers to build applications that are faster, more efficient, and easier to maintain. The App Router uses React Server Components by default, reducing the amount of JavaScript sent to the client and improving initial page load times.

Understanding Next.js is essential for modern React development, as it provides the infrastructure and best practices that most production React applications rely on. Whether you're building a simple landing page or a complex enterprise application, Next.js provides the tools and patterns you need to succeed.

## When to Use Next.js

Next.js is appropriate for virtually any web application project, but it particularly excels in several scenarios that are common in modern web development.

### Production Web Applications

When building applications that will serve real users in production, Next.js provides the reliability, performance, and developer experience needed for success. The framework includes built-in optimizations for images, fonts, scripts, and other assets that directly impact user experience and Core Web Vitals scores.

### Content-Driven Websites

Websites that rely heavily on content, such as blogs, documentation sites, e-commerce platforms, and marketing sites, benefit greatly from Next.js's static generation and incremental static regeneration capabilities. These features allow you to pre-render pages at build time or on-demand, providing fast page loads while keeping content fresh.

### Hybrid Applications

Applications that require a mix of static and dynamic content, authenticated routes, and API endpoints are well-served by Next.js's hybrid rendering model. You can choose different rendering strategies for different pages based on their requirements, all within a single application.

### SEO-Critical Applications

For applications where search engine visibility is important, Next.js's server-side rendering and static generation provide fully rendered HTML to search engine crawlers. Combined with Next.js's automatic image optimization and metadata management, this makes Next.js an excellent choice for SEO-focused projects.

### Server Components

Server Components are the default in the App Router, allowing you to write components that run exclusively on the server. This reduces the JavaScript bundle size sent to the client and enables direct access to backend resources like databases and file systems.

```tsx
// app/components/ProductList.tsx
import { db } from '@/lib/db';

async function getProducts() {
  // This runs on the server
  return db.product.findMany({
    include: {
      category: true,
      reviews: true,
    },
  });
}

export default async function ProductList() {
  const products = await getProducts();
  
  return (
    <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
      {products.map((product) => (
        <div key={product.id} className="border rounded-lg p-4">
          <h2 className="text-xl font-semibold">{product.name}</h2>
          <p className="text-gray-600">{product.category.name}</p>
          <p className="text-lg font-bold mt-2">${product.price}</p>
          <p className="text-sm text-gray-500 mt-2">
            {product.reviews.length} reviews
          </p>
        </div>
      ))}
    </div>
  );
}
```

### Server Actions

Server Actions allow you to define asynchronous server functions that can be called directly from your components, enabling progressive enhancement and secure server-side operations.

```tsx
// app/actions.ts
'use server';

import { revalidatePath } from 'next/cache';
import { z } from 'zod';

const schema = z.object({
  name: z.string().min(1, 'Name is required'),
  email: z.string().email('Invalid email'),
});

export async function createUser(prevState: unknown, formData: FormData) {
  const validatedFields = schema.safeParse({
    name: formData.get('name'),
    email: formData.get('email'),
  });
  
  if (!validatedFields.success) {
    return {
      errors: validatedFields.error.flatten().fieldErrors,
    };
  }
  
  try {
    await db.user.create({
      data: {
        name: validatedFields.data.name,
        email: validatedFields.data.email,
      },
    });
    
    revalidatePath('/users');
    
    return { message: 'User created successfully' };
  } catch (error) {
    return { message: 'Failed to create user' };
  }
}
```

### API Routes

While Server Components and Server Actions handle most server-side logic, Next.js also supports API routes for creating RESTful endpoints.

```tsx
// app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { db } from '@/lib/db';

export async function GET(request: NextRequest) {
  const searchParams = request.nextUrl.searchParams;
  const page = parseInt(searchParams.get('page') || '1');
  const limit = parseInt(searchParams.get('limit') || '10');
  
  const [users, total] = await Promise.all([
    db.user.findMany({
      take: limit,
      skip: (page - 1) * limit,
      orderBy: { createdAt: 'desc' },
    }),
    db.user.count(),
  ]);
  
  return NextResponse.json({
    users,
    pagination: {
      page,
      limit,
      total,
      totalPages: Math.ceil(total / limit),
    },
  });
}

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    
    const user = await db.user.create({
      data: {
        name: body.name,
        email: body.email,
      },
    });
    
    return NextResponse.json(user, { status: 201 });
  } catch (error) {
    return NextResponse.json(
      { error: 'Failed to create user' },
      { status: 400 }
    );
  }
}
```

## Full Example: Blog Application

Here's a complete example of a blog application using Next.js App Router:

```tsx
// lib/posts.ts - Data access layer
import fs from 'fs';
import path from 'path';
import matter from 'gray-matter';

interface Post {
  slug: string;
  title: string;
  date: string;
  excerpt: string;
  content: string;
  tags: string[];
}

const postsDirectory = path.join(process.cwd(), 'content/posts');

export function getAllPosts(): Post[] {
  if (!fs.existsSync(postsDirectory)) {
    return [];
  }
  
  const fileNames = fs.readdirSync(postsDirectory);
  
  return fileNames
    .filter((name) => name.endsWith('.md'))
    .map((fileName) => {
      const fullPath = path.join(postsDirectory, fileName);
      const fileContents = fs.readFileSync(fullPath, 'utf-8');
      const { data, content } = matter(fileContents);
      
      return {
        slug: fileName.replace(/\.md$/, ''),
        title: data.title,
        date: data.date,
        excerpt: data.excerpt,
        content,
        tags: data.tags || [],
      };
    })
    .sort((a, b) => (a.date < b.date ? 1 : -1));
}

export function getPostBySlug(slug: string): Post | null {
  const fullPath = path.join(postsDirectory, `${slug}.md`);
  
  if (!fs.existsSync(fullPath)) {
    return null;
  }
  
  const fileContents = fs.readFileSync(fullPath, 'utf-8');
  const { data, content } = matter(fileContents);
  
  return {
    slug,
    title: data.title,
    date: data.date,
    excerpt: data.excerpt,
    content,
    tags: data.tags || [],
  };
}

export function getRelatedPosts(currentSlug: string, limit = 3): Post[] {
  const posts = getAllPosts();
  const currentPost = posts.find((p) => p.slug === currentSlug);
  
  if (!currentPost) {
    return [];
  }
  
  return posts
    .filter((post) => post.slug !== currentSlug)
    .filter((post) =>
      post.tags.some((tag) => currentPost.tags.includes(tag))
    )
    .slice(0, limit);
}
```

## Common Mistakes

### Mixing App Router and Pages Router

Using both the App Router and the older Pages Router in the same project can lead to confusion and suboptimal patterns. Stick to one router for consistency.

```tsx
// ❌ WRONG - Don't mix patterns
// app/page.tsx (App Router)
import Link from 'next/link';

// pages/about.tsx (Pages Router)
import Link from 'next/link';

// ✅ CORRECT - Use App Router consistently
// app/page.tsx
// app/about/page.tsx
```

### Not Handling Suspense Properly

Forgetting to wrap async components with Suspense can cause hydration mismatches and poor user experience.

```tsx
// ❌ WRONG - Missing Suspense
export default function Page() {
  return (
    <div>
      <h1>Dashboard</h1>
      <UserStats /> {/* Async component without Suspense */}
      <RecentActivity />
    </div>
  );
}

// ✅ CORRECT - Wrap with Suspense
import { Suspense } from 'react';

export default function Page() {
  return (
    <div>
      <h1>Dashboard</h1>
      <Suspense fallback={<UserStatsSkeleton />}>
        <UserStats />
      </Suspense>
      <Suspense fallback={<ActivitySkeleton />}>
        <RecentActivity />
      </Suspense>
    </div>
  );
}
```

### Incorrectly Using useState in Server Components

Server Components cannot use React hooks like useState because they don't execute on the client. Use Server Actions and pass handlers to Client Components instead.

```tsx
// ❌ WRONG - useState in Server Component
export default function ServerComponent() {
  const [count, setCount] = useState(0); // Error!
  
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

// ✅ CORRECT - Separate Client Component
// app/components/Counter.tsx
'use client';

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

// app/page.tsx
import Counter from '@/components/Counter';

export default function Page() {
  return <Counter />;
}
```
