# Next.js App Router & Server Architecture

## Overview

The Next.js App Router introduces a modern rendering architecture based on React Server Components.

By default, components run on the server, reducing client-side JavaScript and improving:

- Performance.
- SEO.
- Initial page loading.
- Security.

---

# Key Concepts

## React Server Components

Server Components:

- Execute only on the server.
- Can access server resources directly.
- Send less JavaScript to browsers.

They are useful for:

- Database queries.
- Static content.
- Server-side rendering.

---

## Client Components

Client Components require:

```tsx
"use client";

They are used for:

User interactions.
Browser APIs.
React hooks like useState and useEffect.
Server Actions

Server Actions allow secure server-side functions to handle mutations.

Example:

"use server";

import { revalidatePath } from "next/cache";
import { z } from "zod";


const userSchema = z.object({

  name: z.string().min(2),

  email: z.string().email(),

});


export async function createUser(
  formData: FormData
) {

  const result =
    userSchema.safeParse({

      name: formData.get("name"),

      email: formData.get("email"),

    });



  if (!result.success) {

    return {
      success: false,
      error: "Invalid data",
    };

  }



  console.log(
    "Saving user:",
    result.data
  );


  revalidatePath(
    "/dashboard/users"
  );


  return {

    success: true,

    message:
      "User created successfully",

  };

}
Streaming with Suspense

Streaming allows parts of a page to load while other data is still being fetched.

Example:

import {
  Suspense
} from "react";


export default function Page(){

  return (

    <Suspense fallback={<p>Loading...</p>}>

      <UsersList />

    </Suspense>

  );

}


async function UsersList(){

  const users =
    await getUsers();


  return (

    <ul>

      {users.map(user => (

        <li key={user.id}>

          {user.name}

        </li>

      ))}

    </ul>

  );

}

Best Practices
Avoid Browser APIs in Server Components

Do not use:

window.localStorage

inside Server Components.

Move browser logic into Client Components.

Validate Server Inputs

Always validate:

Forms.
API responses.
User input.

Libraries like Zod help prevent invalid data.

Manage Cache Carefully

Use:

revalidatePath
revalidateTag
fetch caching options

to avoid showing outdated information.
