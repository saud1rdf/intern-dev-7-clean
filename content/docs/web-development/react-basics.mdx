# React High-Performance State Architecture

## Introduction

React's declarative model makes building UIs intuitive, but without deliberate state architecture, applications become slow, buggy, and hard to maintain. This guide covers production-ready patterns for managing state at scale — from component-local state to shared global state, server state, and URL state.

Understanding how to categorize and manage different types of state is the single most important skill for building performant React applications. Misclassifying state leads to over-engineering (global state for local UI) or bugs (local state that should be shared).

Every pattern in this article is written as clean, self-contained, typed code you can paste into a Next.js or Vite project and run immediately. The practical tasks at the end show you how to build and verify each pattern in your local environment with real commands.

## Prerequisites

Before you begin, you should be comfortable with:

- **JavaScript fundamentals** — variables, functions, arrays, `async`/`await`. Review the [JavaScript Essentials](https://developer.mozilla.org/en-US/docs/Web/JavaScript) guide if needed.
- **React basics** — components, props, JSX, and the `useState`/`useEffect` hooks. See [React's "Describing the UI" guide](https://react.dev/learn/describing-ui).
- **Basic TypeScript** — type annotations for props and functions.
- **A local development environment** — Node.js 18+, npm, and either an existing React project or the ability to scaffold one with `create-next-app` or `create-vite`. Every task below includes the exact commands.

> You do not need to master everything at once. The article is organized so you can read the concepts, then run the matching task at the end of each major section.

## Learning Objectives

By the end of this article you will be able to:

- Categorize state into the four types that matter: local UI, shared UI, server, and URL state.
- Decide correctly between `useState` and `useReducer` for a given piece of logic.
- Build scalable shared state using the **split context pattern** without causing mass re-renders.
- Manage server state with TanStack Query, including optimistic updates with automatic rollback.
- Sync filters, search, and pagination to the URL so views are shareable and deep-linkable.
- Apply memoization (`memo`, `useMemo`, `useCallback`) and virtualization deliberately — only where they pay off.

## Core Concepts

### State Categories

Not all state is created equal. Every piece of state in your React app falls into one of four categories:

| State Type | Lifetime | Scope | Examples | Tools |
|------------|----------|-------|----------|-------|
| **Local UI State** | Component mount | Single component | Input values, modal open/closed, dropdown selection | `useState`, `useReducer` |
| **Shared UI State** | App session | Multiple components | Theme, user preferences, sidebar toggle | Context + `useReducer`, Zustand, Jotai |
| **Server/Remote State** | Cache lifetime | Global (shared) | API data, user profile, permissions | TanStack Query, SWR, RTK Query |
| **URL State** | Browser session | Global (shareable) | Filters, search query, pagination, tabs | `useSearchParams`, custom hooks |

**Rule of thumb:** start with the most local option that works. Move state "up" only when necessary.

- State used by exactly one component belongs in that component.
- State needed by a few components belongs in shared state near their common parent.
- State owned by the server belongs in a server-state library, never in `useState`.
- View state that should survive a page reload or be shared via a link belongs in the URL.

### Local UI State: `useState` and `useReducer`

#### When to Use `useState`

Simple, independent values that don't involve complex transitions. Note the idiomatic details: typed props, a typed change handler, and accessibility attributes.

```tsx
import { useState } from "react";
import type { ChangeEvent } from "react";

interface SearchInputProps {
  onSearch: (query: string) => void;
  placeholder?: string;
}

export function SearchInput({
  onSearch,
  placeholder = "Search...",
}: SearchInputProps) {
  const [query, setQuery] = useState("");
  const [isFocused, setIsFocused] = useState(false);

  const handleChange = (event: ChangeEvent<HTMLInputElement>) => {
    const value = event.target.value;
    setQuery(value);
    onSearch(value);
  };

  const handleFocus = () => setIsFocused(true);
  const handleBlur = () => setIsFocused(false);

  return (
    <input
      type="search"
      value={query}
      onChange={handleChange}
      onFocus={handleFocus}
      onBlur={handleBlur}
      placeholder={placeholder}
      aria-label={placeholder}
      className={isFocused ? "focused" : ""}
    />
  );
}
```

#### When to Use `useReducer`

Complex state logic with multiple sub-values, or when the next state depends on the previous. The classic example is a form with values, validation errors, touched flags, and a submitting flag — all transitions funneled through one reducer makes the logic testable and predictable.

```tsx
import { useReducer } from "react";
import type { FormEvent } from "react";

type FormValues = Record<string, string>;
type FormErrors = Record<string, string>;

interface FormState {
  values: FormValues;
  errors: FormErrors;
  touched: Record<string, boolean>;
  isSubmitting: boolean;
}

type FormAction =
  | { type: "SET_FIELD"; field: string; value: string }
  | { type: "BLUR_FIELD"; field: string }
  | { type: "SET_ERROR"; field: string; error: string }
  | { type: "START_SUBMIT" }
  | { type: "SUBMIT_SUCCESS" }
  | { type: "SUBMIT_FAILURE"; errors: FormErrors }
  | { type: "RESET" };

const initialState: FormState = {
  values: {},
  errors: {},
  touched: {},
  isSubmitting: false,
};

function formReducer(state: FormState, action: FormAction): FormState {
  switch (action.type) {
    case "SET_FIELD":
      return {
        ...state,
        values: { ...state.values, [action.field]: action.value },
        errors: { ...state.errors, [action.field]: "" }, // clear error on change
      };
    case "BLUR_FIELD":
      return {
        ...state,
        touched: { ...state.touched, [action.field]: true },
      };
    case "SET_ERROR":
      return {
        ...state,
        errors: { ...state.errors, [action.field]: action.error },
      };
    case "START_SUBMIT":
      return { ...state, isSubmitting: true };
    case "SUBMIT_SUCCESS":
      return { ...state, isSubmitting: false, touched: {} };
    case "SUBMIT_FAILURE":
      return { ...state, isSubmitting: false, errors: action.errors };
    case "RESET":
      return initialState;
    default:
      return state;
  }
}

interface UseFormOptions {
  initialValues?: FormValues;
  validate?: (values: FormValues) => FormErrors;
  onSubmit: (values: FormValues) => Promise<void>;
}

export function useForm({
  initialValues = {},
  validate,
  onSubmit,
}: UseFormOptions) {
  const [state, dispatch] = useReducer(formReducer, {
    ...initialState,
    values: initialValues,
  });

  const handleChange = (field: string, value: string) => {
    dispatch({ type: "SET_FIELD", field, value });
  };

  const handleBlur = (field: string) => {
    dispatch({ type: "BLUR_FIELD", field });
  };

  const handleSubmit = async (event: FormEvent<HTMLFormElement>) => {
    event.preventDefault();
    dispatch({ type: "START_SUBMIT" });

    const errors = validate ? validate(state.values) : {};
    if (Object.keys(errors).length > 0) {
      Object.entries(errors).forEach(([field, error]) => {
        dispatch({ type: "SET_ERROR", field, error });
      });
      dispatch({ type: "SUBMIT_FAILURE", errors });
      return;
    }

    try {
      await onSubmit(state.values);
      dispatch({ type: "SUBMIT_SUCCESS" });
    } catch (error) {
      const message =
        error instanceof Error ? error.message : "Submission failed";
      dispatch({ type: "SUBMIT_FAILURE", errors: { form: message } });
    }
  };

  const reset = () => dispatch({ type: "RESET" });

  return {
    ...state,
    handleChange,
    handleBlur,
    handleSubmit,
    reset,
  };
}
```

### Shared UI State: The Split Context Pattern

A common mistake is putting everything in one Context, causing all consumers to re-render when any value changes. The **split context pattern** separates state from dispatch into two contexts, then exposes selective hooks so a component only re-renders when the slice it cares about changes.

```tsx
// contexts/AppContext.tsx
"use client";

import { createContext, useContext, useReducer } from "react";
import type { Dispatch, ReactNode } from "react";

interface User {
  id: string;
  name: string;
  email: string;
  avatar?: string;
}

interface AppState {
  theme: "light" | "dark";
  sidebarOpen: boolean;
  user: User | null;
}

type AppAction =
  | { type: "TOGGLE_THEME" }
  | { type: "SET_SIDEBAR"; payload: boolean }
  | { type: "SET_USER"; payload: User | null };

const initialState: AppState = {
  theme: "light",
  sidebarOpen: false,
  user: null,
};

// Two separate contexts: consumers of state and consumers of dispatch
const StateContext = createContext<AppState | undefined>(undefined);
const DispatchContext = createContext<Dispatch<AppAction> | undefined>(undefined);

function appReducer(state: AppState, action: AppAction): AppState {
  switch (action.type) {
    case "TOGGLE_THEME":
      return { ...state, theme: state.theme === "light" ? "dark" : "light" };
    case "SET_SIDEBAR":
      return { ...state, sidebarOpen: action.payload };
    case "SET_USER":
      return { ...state, user: action.payload };
    default:
      return state;
  }
}

interface AppProviderProps {
  children: ReactNode;
}

export function AppProvider({ children }: AppProviderProps) {
  const [state, dispatch] = useReducer(appReducer, initialState);

  return (
    <StateContext.Provider value={state}>
      <DispatchContext.Provider value={dispatch}>
        {children}
      </DispatchContext.Provider>
    </StateContext.Provider>
  );
}

// Guarded accessors - throw early instead of failing silently
function useAppState(): AppState {
  const context = useContext(StateContext);
  if (!context) {
    throw new Error("useAppState must be used within AppProvider");
  }
  return context;
}

function useAppDispatch(): Dispatch<AppAction> {
  const context = useContext(DispatchContext);
  if (!context) {
    throw new Error("useAppDispatch must be used within AppProvider");
  }
  return context;
}

// Selective hooks - a component using useTheme() only re-renders
// when theme changes, never when sidebarOpen or user changes.
export function useTheme(): ["light" | "dark", () => void] {
  const { theme } = useAppState();
  const dispatch = useAppDispatch();
  return [theme, () => dispatch({ type: "TOGGLE_THEME" })];
}

export function useSidebar(): [boolean, (open: boolean) => void] {
  const { sidebarOpen } = useAppState();
  const dispatch = useAppDispatch();
  return [
    sidebarOpen,
    (open: boolean) => dispatch({ type: "SET_SIDEBAR", payload: open }),
  ];
}

export function useUser(): [User | null, (user: User | null) => void] {
  const { user } = useAppState();
  const dispatch = useAppDispatch();
  return [
    user,
    (nextUser: User | null) => dispatch({ type: "SET_USER", payload: nextUser }),
  ];
}
```

**Why this works:** components using `useTheme()` only re-render when `theme` changes, not when `sidebarOpen` or `user` changes. The two-context split means dispatch-only consumers (event handlers, action creators) never re-render at all, because the `dispatch` function reference is stable.

### Server State: TanStack Query (React Query)

Server state is fundamentally different from client state:

- **Owned by the server**, not your app.
- **Async** — requires fetching, caching, invalidation, and retries.
- **Shared** — many components need the same data.
- **Stale** — it becomes outdated over time.

**Never put server state in `useState` or Context manually.** Use TanStack Query (v5), which centralizes caching, background refetching, and retries.

```tsx
// lib/queries.ts
import { queryOptions } from "@tanstack/react-query";

export interface User {
  id: string;
  name: string;
  email: string;
  avatar?: string;
  role: "admin" | "user" | "viewer";
  createdAt: string;
}

export interface UserFilters {
  search?: string;
  status?: "all" | "active" | "inactive";
  page?: number;
  sort?: "name" | "email" | "createdAt";
}

export const userQueryOptions = (userId: string) =>
  queryOptions({
    queryKey: ["user", userId],
    queryFn: async (): Promise<User> => {
      const response = await fetch(`/api/users/${userId}`);
      if (!response.ok) {
        throw new Error(`Failed to fetch user: ${response.statusText}`);
      }
      return response.json();
    },
    staleTime: 5 * 60 * 1000, // 5 minutes - fresh cache
    gcTime: 10 * 60 * 1000, // 10 minutes - kept in cache after unmount
    retry: 2,
    refetchOnWindowFocus: false,
  });

export const usersListQueryOptions = (filters: UserFilters) =>
  queryOptions({
    queryKey: ["users", filters],
    queryFn: async (): Promise<{ users: User[]; total: number }> => {
      const params = new URLSearchParams();
      Object.entries(filters).forEach(([key, value]) => {
        if (value !== undefined && value !== "") {
          params.set(key, String(value));
        }
      });
      const query = params.toString();
      const response = await fetch(`/api/users?${query}`);
      if (!response.ok) {
        throw new Error(`Failed to fetch users: ${response.statusText}`);
      }
      return response.json();
    },
    staleTime: 30 * 1000,
    placeholderData: (previousData) => previousData, // keep old data while fetching
  });
```

```tsx
// components/UserProfile.tsx
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { userQueryOptions } from "@/lib/queries";
import type { User } from "@/lib/queries";

interface UserProfileProps {
  userId: string;
}

export function UserProfile({ userId }: UserProfileProps) {
  const { data: user, isLoading, error } = useQuery(userQueryOptions(userId));
  const queryClient = useQueryClient();

  const updateMutation = useMutation({
    mutationFn: async (data: Partial<User>): Promise<User> => {
      const response = await fetch(`/api/users/${userId}`, {
        method: "PATCH",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(data),
      });
      if (!response.ok) {
        throw new Error("Failed to update user");
      }
      return response.json();
    },
    // Optimistic update: apply locally first, roll back on error
    onMutate: async (newData) => {
      await queryClient.cancelQueries({ queryKey: ["user", userId] });

      const previousUser = queryClient.getQueryData<User>(["user", userId]);

      if (previousUser) {
        queryClient.setQueryData<User>(["user", userId], {
          ...previousUser,
          ...newData,
        });
      }

      return { previousUser };
    },
    onError: (_error, _newData, context) => {
      if (context?.previousUser) {
        queryClient.setQueryData(["user", userId], context.previousUser);
      }
    },
    onSettled: () => {
      // Always reconcile with the server after success or failure
      queryClient.invalidateQueries({ queryKey: ["user", userId] });
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });

  if (isLoading) {
    return <div className="skeleton" aria-label="Loading user profile..." />;
  }
  if (error) {
    return (
      <div className="error" role="alert">
        Failed to load: {error.message}
      </div>
    );
  }
  if (!user) {
    return <div className="not-found">User not found</div>;
  }

  return (
    <div className="user-profile">
      <h1>{user.name}</h1>
      <p>{user.email}</p>
      <button
        type="button"
        onClick={() => updateMutation.mutate({ name: "Updated Name" })}
        disabled={updateMutation.isPending}
        aria-busy={updateMutation.isPending}
      >
        {updateMutation.isPending ? "Saving..." : "Update Name"}
      </button>
      {updateMutation.isError && (
        <div className="error" role="alert">
          Update failed: {updateMutation.error?.message}
        </div>
      )}
    </div>
  );
}
```

### URL State: Shareable, Deep-Linkable Filters

URL state is **view state that belongs in the address bar** — filters, search, pagination, tabs. The benefits:

- **Shareable** — copy the URL, send it to a colleague, they see the same view.
- **Bookmarkable** — save filter combinations for later.
- **Back/Forward** — browser history works naturally.
- **SSR-friendly** — the initial render matches the URL, so the server can render the same view.

#### Custom Hook for URL State

The idiomatic approach reads the current value straight from `useSearchParams` and pushes a new URL on update. No external store is needed — the browser URL is the source of truth.

```tsx
// hooks/useURLQueryState.ts
"use client";

import { useCallback } from "react";
import { usePathname, useRouter, useSearchParams } from "next/navigation";

interface UseURLQueryStateOptions<T> {
  parse?: (raw: string) => T;
  serialize?: (value: T) => string;
}

export function useURLQueryState<T extends string = string>(
  key: string,
  defaultValue: T,
  options: UseURLQueryStateOptions<T> = {}
): [T, (value: T) => void] {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  const { parse, serialize } = {
    parse: options.parse ?? ((raw: string) => raw as T),
    serialize: options.serialize ?? ((value: T) => value),
  };

  // Derived directly from the URL - always in sync with browser navigation
  const rawValue = searchParams.get(key);
  const value: T = rawValue === null ? defaultValue : parse(rawValue);

  const setValue = useCallback(
    (nextValue: T) => {
      const nextParams = new URLSearchParams(searchParams.toString());

      if (nextValue === defaultValue) {
        nextParams.delete(key);
      } else {
        nextParams.set(key, serialize(nextValue));
      }

      const query = nextParams.toString();
      router.push(query ? `${pathname}?${query}` : pathname, { scroll: false });
    },
    [router, searchParams, pathname, key, defaultValue, serialize]
  );

  return [value, setValue];
}
```

Usage with type-safe unions — every filter lives in the URL, and the URL remains the single source of truth:

## Performance Optimization Techniques

Optimize only when something is measurably slow. These four tools are the ones that matter for state-heavy UIs.

### 1. `React.memo` for Component Memoization

`memo` skips re-renders when props are shallow-equal. It pays off when a component renders often, receives stable props, and its render is expensive.

```tsx
import { memo } from "react";

interface UserCardProps {
  user: {
    id: string;
    name: string;
    email: string;
    avatar?: string;
  };
  onEdit: (userId: string) => void;
}

const UserCardComponent = memo(function UserCardComponent({
  user,
  onEdit,
}: UserCardProps) {
  return (
    <article className="user-card">
      {user.avatar && <img src={user.avatar} alt="" aria-hidden="true" />}
      <div className="user-info">
        <h3>{user.name}</h3>
        <p>{user.email}</p>
      </div>
      <button type="button" onClick={() => onEdit(user.id)} className="edit-btn">
        Edit
      </button>
    </article>
  );
});

// Custom comparison only when shallow equality is not enough
export const UserCard = memo(UserCardComponent, (prev, next) => {
  return (
    prev.user.id === next.user.id &&
    prev.user.name === next.user.name &&
    prev.user.email === next.user.email &&
    prev.onEdit === next.onEdit
  );
});
```

### 2. `useMemo` for Expensive Computations

`useMemo` caches the result of a computation between renders. Only use it for genuinely expensive work (filtering and sorting large arrays qualifies).

```tsx
import { useMemo } from "react";

interface UserListProps {
  users: Array<{ id: string; name: string; email: string; role: string }>;
  filter: string;
  sort: "name" | "email" | "role";
}

export function UserList({ users, filter, sort }: UserListProps) {
  const filteredAndSorted = useMemo(() => {
    const needle = filter.toLowerCase();
    const filtered = users.filter(
      (user) =>
        user.name.toLowerCase().includes(needle) ||
        user.email.toLowerCase().includes(needle)
    );

    return [...filtered].sort((a, b) => {
      const aValue = a[sort];
      const bValue = b[sort];
      if (aValue < bValue) return -1;
      if (aValue > bValue) return 1;
      return 0;
    });
  }, [users, filter, sort]);

  return (
    <ul className="user-list" role="list">
      {filteredAndSorted.map((user) => (
        <UserCard key={user.id} user={user} onEdit={() => {}} />
      ))}
    </ul>
  );
}
```

### 3. `useCallback` for Stable Function References

`useCallback` keeps a function reference stable across renders. This matters when the function is a dependency of `useEffect`, or a prop of a `memo`ized child passed down a list.

```tsx
import { useCallback } from "react";
import { useQueryClient } from "@tanstack/react-query";

interface UserListWithActionsProps {
  users: Array<{ id: string; name: string; isEditing: boolean }>;
}

export function UserListWithActions({ users }: UserListWithActionsProps) {
  const queryClient = useQueryClient();

  const handleEdit = useCallback(
    (userId: string) => {
      queryClient.setQueryData(["user", userId], (old) => {
        const current = old as { isEditing: boolean } | undefined;
        return { ...current, isEditing: true };
      });
    },
    [queryClient]
  );

  const handleSave = useCallback(
    async (userId: string, data: Partial<{ name: string; email: string }>) => {
      const response = await fetch(`/api/users/${userId}`, {
        method: "PATCH",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(data),
      });
      if (!response.ok) {
        throw new Error("Failed to save");
      }
      await queryClient.invalidateQueries({ queryKey: ["user", userId] });
    },
    [queryClient]
  );

  return (
    <ul>
      {users.map((user) => (
        <UserCard
          key={user.id}
          user={user}
          onEdit={handleEdit}
          onSave={handleSave}
        />
      ))}
    </ul>
  );
}
```

> Note: `UserCard` in this snippet would need an optional `onSave` prop — add it to the props interface when combining these examples in one file.

### 4. Virtualized Lists for Large Data

Rendering 10,000 DOM nodes at once freezes the main thread. Virtualization renders only the rows visible in the viewport plus a small overscan buffer.

```tsx
import { memo } from "react";
import { FixedSizeList as List } from "react-window";
import type { CSSProperties } from "react";

interface VirtualizedUserListProps {
  users: Array<{ id: string; name: string; email: string }>;
  height?: number;
  itemSize?: number;
}

const VirtualizedRow = memo(function VirtualizedRow({
  index,
  style,
  data,
}: {
  index: number;
  style: CSSProperties;
  data: Array<{ id: string; name: string; email: string }>;
}) {
  const user = data[index];
  return (
    <div style={style} className="virtualized-row">
      <UserCard user={user} onEdit={() => {}} />
    </div>
  );
});

export function VirtualizedUserList({
  users,
  height = 600,
  itemSize = 120,
}: VirtualizedUserListProps) {
  if (users.length === 0) {
    return <div className="empty-state">No users to display</div>;
  }

  return (
    <List
      height={height}
      itemCount={users.length}
      itemSize={itemSize}
      width="100%"
      itemData={users}
      overscanCount={5}
    >
      {VirtualizedRow}
    </List>
  );
}
```

## Full Example: Task Dashboard with All State Types

This dashboard combines every pattern in one screen: URL state for filters, local state for the create form, shared state for theme/sidebar via split context, and TanStack Query for the task list with optimistic create and toggle mutations.

### File: `lib/queries.ts`

```tsx
import { queryOptions } from "@tanstack/react-query";

export type TaskStatus = "pending" | "completed";

export interface Task {
  id: string;
  title: string;
  status: TaskStatus;
  createdAt: string;
}

const BASE_URL = "/api";

export const tasksQueryOptions = (filters: {
  search?: string;
  status?: TaskStatus | "all";
  page?: number;
}) =>
  queryOptions({
    queryKey: ["tasks", filters],
    queryFn: async (): Promise<{ tasks: Task[]; total: number }> => {
      const params = new URLSearchParams();
      if (filters.search) params.set("search", filters.search);
      if (filters.status && filters.status !== "all") {
        params.set("status", filters.status);
      }
      params.set("page", String(filters.page ?? 1));

      const response = await fetch(`${BASE_URL}/tasks?${params}`);
      if (!response.ok) {
        throw new Error(`Failed to fetch tasks: ${response.statusText}`);
      }
      return response.json();
    },
    staleTime: 30_000,
    placeholderData: (previousData) => previousData,
  });

export const createTask = async (input: {
  title: string;
  status: TaskStatus;
}): Promise<Task> => {
  const response = await fetch(`${BASE_URL}/tasks`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(input),
  });
  if (!response.ok) throw new Error("Failed to create task");
  return response.json();
};

export const toggleTask = async (task: Task): Promise<Task> => {
  const response = await fetch(`${BASE_URL}/tasks/${task.id}`, {
    method: "PATCH",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      status: task.status === "completed" ? "pending" : "completed",
    }),
  });
  if (!response.ok) throw new Error("Failed to toggle task");
  return response.json();
};
```

### File: `app/dashboard/TaskDashboard.tsx`

```tsx
"use client";

import { useState } from "react";
import type { FormEvent } from "react";
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { useURLQueryState } from "@/hooks/useURLQueryState";
import { useSidebar, useTheme } from "@/contexts/AppContext";
import { createTask, tasksQueryOptions, toggleTask } from "@/lib/queries";
import type { Task, TaskStatus } from "@/lib/queries";

const PAGE_SIZE = 10;

export function TaskDashboard() {
  // URL State - shareable filters and pagination
  const [search, setSearch] = useURLQueryState("search", "");
  const [status, setStatus] = useURLQueryState<TaskStatus | "all">(
    "status",
    "all"
  );
  const [page, setPage] = useURLQueryState("page", "1");
  const pageNumber = Number(page);

  // Local UI State - component-specific form
  const [newTaskTitle, setNewTaskTitle] = useState("");

  // Shared UI State - consumed from the split context
  const [theme, toggleTheme] = useTheme();
  const [sidebarOpen, setSidebarOpen] = useSidebar();

  // Server State - tasks from the API, cached by TanStack Query
  const { data, isLoading, error } = useQuery(
    tasksQueryOptions({ search, status, page: pageNumber })
  );

  const queryClient = useQueryClient();
  const hasNextPage = (data?.total ?? 0) > pageNumber * PAGE_SIZE;

  const createMutation = useMutation({
    mutationFn: createTask,
    // Optimistic create with rollback
    onMutate: async (input) => {
      await queryClient.cancelQueries({ queryKey: ["tasks"] });
      const previousData = queryClient.getQueryData<{
        tasks: Task[];
        total: number;
      }>(["tasks"]);

      queryClient.setQueryData<{ tasks: Task[]; total: number }>(
        ["tasks"],
        (old) => ({
          tasks: [
            {
              id: `temp-${Date.now()}`,
              title: input.title,
              status: input.status,
              createdAt: new Date().toISOString(),
            },
            ...(old?.tasks ?? []),
          ],
          total: (old?.total ?? 0) + 1,
        })
      );

      return { previousData };
    },
    onError: (_error, _input, context) => {
      if (context?.previousData) {
        queryClient.setQueryData(["tasks"], context.previousData);
      }
    },
    onSettled: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  const toggleMutation = useMutation({
    mutationFn: toggleTask,
    // Optimistic toggle with rollback
    onMutate: async (task) => {
      await queryClient.cancelQueries({ queryKey: ["tasks"] });
      const previousData = queryClient.getQueryData<{
        tasks: Task[];
        total: number;
      }>(["tasks"]);

      queryClient.setQueryData<{ tasks: Task[]; total: number }>(
        ["tasks"],
        (old) =>
          old
            ? {
                ...old,
                tasks: old.tasks.map((item) =>
                  item.id === task.id
                    ? {
                        ...item,
                        status:
                          item.status === "completed" ? "pending" : "completed",
                      }
                    : item
                ),
              }
            : old
      );

      return { previousData };
    },
    onError: (_error, _task, context) => {
      if (context?.previousData) {
        queryClient.setQueryData(["tasks"], context.previousData);
      }
    },
    onSettled: () => queryClient.invalidateQueries({ queryKey: ["tasks"] }),
  });

  const handleCreate = (event: FormEvent<HTMLFormElement>) => {
    event.preventDefault();
    const title = newTaskTitle.trim();
    if (!title || createMutation.isPending) return;
    createMutation.mutate({ title, status: "pending" });
    setNewTaskTitle("");
  };

  if (isLoading) {
    return <div className="loading" aria-label="Loading tasks..." />;
  }
  if (error) {
    return (
      <div className="error" role="alert">
        Failed to load tasks: {error.message}
      </div>
    );
  }

  return (
    <div className="dashboard">
      <header className="dashboard-header">
        <button type="button" onClick={toggleTheme} className="icon-button">
          {theme === "light" ? "Dark mode" : "Light mode"}
        </button>
        <button
          type="button"
          onClick={() => setSidebarOpen(!sidebarOpen)}
          className="icon-button"
        >
          {sidebarOpen ? "Close sidebar" : "Open sidebar"}
        </button>
      </header>

      <aside className={sidebarOpen ? "sidebar open" : "sidebar"}>
        <nav aria-label="Task status filters">
          <button
            type="button"
            onClick={() => setStatus("all")}
            className={status === "all" ? "active" : ""}
          >
            All Tasks
          </button>
          <button
            type="button"
            onClick={() => setStatus("pending")}
            className={status === "pending" ? "active" : ""}
          >
            Pending
          </button>
          <button
            type="button"
            onClick={() => setStatus("completed")}
            className={status === "completed" ? "active" : ""}
          >
            Completed
          </button>
        </nav>
      </aside>

      <main className="main-content">
        <form onSubmit={handleCreate} className="create-form">
          <label htmlFor="new-task" className="sr-only">
            New task title
          </label>
          <input
            id="new-task"
            type="text"
            value={newTaskTitle}
            onChange={(event) => setNewTaskTitle(event.target.value)}
            placeholder="New task title..."
            disabled={createMutation.isPending}
          />
          <button
            type="submit"
            disabled={createMutation.isPending || !newTaskTitle.trim()}
          >
            {createMutation.isPending ? "Creating..." : "Add Task"}
          </button>
        </form>

        <div className="filters" role="search" aria-label="Task filters">
          <label htmlFor="task-search" className="sr-only">
            Search tasks
          </label>
          <input
            id="task-search"
            type="search"
            value={search}
            onChange={(event) => setSearch(event.target.value)}
            placeholder="Search tasks..."
          />
        </div>

        {data?.tasks.length === 0 ? (
          <p className="empty-state">
            No tasks found.{" "}
            {search ? "Try a different search." : "Create your first task!"}
          </p>
        ) : (
          <ul className="task-list" role="list">
            {data?.tasks.map((task) => (
              <li
                key={task.id}
                className={`task-item ${task.status}`}
              >
                <label>
                  <input
                    type="checkbox"
                    checked={task.status === "completed"}
                    onChange={() => toggleMutation.mutate(task)}
                    aria-label={`Mark "${task.title}" as ${
                      task.status === "completed" ? "pending" : "completed"
                    }`}
                  />
                  <span>{task.title}</span>
                </label>
              </li>
            ))}
          </ul>
        )}

        <div className="pagination" role="navigation" aria-label="Pagination">
          <button
            type="button"
            onClick={() => setPage(String(pageNumber - 1))}
            disabled={pageNumber <= 1}
            aria-label="Previous page"
          >
            Previous
          </button>
          <span aria-current="page">Page {pageNumber}</span>
          <button
            type="button"
            onClick={() => setPage(String(pageNumber + 1))}
            disabled={!hasNextPage}
            aria-label="Next page"
          >
            Next
          </button>
        </div>
      </main>
    </div>
  );
}
```

## Common Mistakes

### Putting Everything in Global State

Global state for a modal that one component controls adds indirection and causes unrelated re-renders.

```tsx
// ❌ WRONG: global store for purely local UI
const useStore = create((set) => ({
  isModalOpen: false,
  toggleModal: () => set((state) => ({ isModalOpen: !state.isModalOpen })),
}));

// ✅ CORRECT: keep UI-only state local
function Parent() {
  const [isModalOpen, setIsModalOpen] = useState(false);
  return <Child onOpen={() => setIsModalOpen(true)} />;
}
```

### Not Invalidating Queries After Mutations

Mutations change server data; the cache must be told to refetch. Skipping invalidation shows stale data until a manual refresh.

```tsx
// ❌ WRONG: data stays stale
const mutation = useMutation({ mutationFn: updateUser });
mutation.mutate(data);

// ✅ CORRECT: invalidate every query that derived from this data
const mutation = useMutation({
  mutationFn: updateUser,
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["user", userId] });
    queryClient.invalidateQueries({ queryKey: ["users"] });
  },
});
```

### Storing Derived State in `useState`

State that can be computed from other state is redundant and drifts out of sync.

```tsx
// ❌ WRONG: fullName can get out of sync
const [firstName, setFirstName] = useState("");
const [lastName, setLastName] = useState("");
const [fullName, setFullName] = useState(""); // redundant!

// ✅ CORRECT: compute during render
const [firstName, setFirstName] = useState("");
const [lastName, setLastName] = useState("");
const fullName = `${firstName} ${lastName}`.trim(); // always in sync
```

### Creating Components Inside Render

A component defined inside another component is recreated every render, which unmounts/remounts the entire subtree and destroys state — memoization will not help.

```tsx
// ❌ WRONG: new type every render -> full remount of the subtree
function Parent() {
  const Child = () => <div>Hi</div>;
  return <Child />;
}

// ✅ CORRECT: define at module scope
function Child() {
  return <div>Hi</div>;
}

function Parent() {
  return <Child />;
}
```

### Missing Error Boundaries

An uncaught render error unmounts the whole tree. Error boundaries scope the blast radius and show a fallback.

```tsx
import { Component } from "react";
import type { ErrorInfo, ReactNode } from "react";

interface ErrorBoundaryProps {
  children: ReactNode;
  fallback: ReactNode;
}

interface ErrorBoundaryState {
  hasError: boolean;
  error: Error | null;
}

// ✅ CORRECT: class boundary - the only API for catching render errors
export class ErrorBoundary extends Component<
  ErrorBoundaryProps,
  ErrorBoundaryState
> {
  constructor(props: ErrorBoundaryProps) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error: Error): ErrorBoundaryState {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    // Send to your error reporting service
    console.error("Error caught by boundary:", error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback;
    }
    return this.props.children;
  }
}
```

**Steps:**

2. Create the QueryClient provider at `app/providers.tsx`:
   ```tsx
   "use client";

   import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
   import { useState } from "react";
   import type { ReactNode } from "react";

   export function Providers({ children }: { children: ReactNode }) {
     const [queryClient] = useState(() => new QueryClient());
     return (
       <QueryClientProvider client={queryClient}>
         {children}
       </QueryClientProvider>
     );
   }
   ```

3. Wrap the layout by editing `app/layout.tsx` so its `<body>` contains:
   ```tsx

   ```

4. Replace `app/page.tsx` with a component that uses `useQuery` against [JSONPlaceholder](https://jsonplaceholder.typicode.com/) — a free, public REST API:
   ```tsx
   "use client";

   import { useQuery } from "@tanstack/react-query";
   import { queryOptions } from "@tanstack/react-query";

   interface User {
     id: number;
     name: string;
     email: string;
   }

   const usersQuery = queryOptions({
     queryKey: ["users"],
     queryFn: async (): Promise<User[]> => {
       const response = await fetch(
         "https://jsonplaceholder.typicode.com/users"
       );
       if (!response.ok) throw new Error("Failed to fetch users");
       return response.json();
     },
     staleTime: 5 * 60 * 1000,
   });

   export default function Home() {
     const { data, isLoading, error, refetch } = useQuery(usersQuery);

     if (isLoading) return <p>Loading users...</p>;
     if (error) return <p role="alert">Error: {error.message}</p>;

     return (
       <main>
         <button type="button" onClick={() => refetch()}>
           Refetch
         </button>
         <ul>
           {data?.map((user) => (
             <li key={user.id}>
               {user.name} &lt;{user.email}&gt;
             </li>
           ))}
         </ul>
       </main>
     );
   }
   ```

5. Run the dev server:
   ```bash
   npm run dev
   ```
   Open <http://localhost:3000>.

**Verify:** The page shows ten user names from the API. In the Network tab, click **Refetch** — you should see a zero-millisecond response served from the cache because `staleTime` is 5 minutes, and the "Refetch" button is how you reconcile a stale cache on demand.

   ```tsx
   const THEME_KEY = "theme";

   function getInitialTheme(): "light" | "dark" {
     if (typeof window === "undefined") return "light";
   ```

### Task 4: Implement Optimistic Updates with Rollback

**Objective:** Turn the "Refetch" demo into a proper mutation flow: rename a user optimistically, roll back automatically when the server rejects it, and reconcile with `invalidateQueries`.

**Steps:**

1. Install nothing new — TanStack Query ships `useMutation`. Add to `app/page.tsx` a button per user row that optimistically renames:
   ```tsx
   "use client";

   import { useMutation, useQueryClient } from "@tanstack/react-query";

   // Inside the component:
   const queryClient = useQueryClient();

   const renameMutation = useMutation({
     mutationFn: async ({ id }: { id: number }) => {
       const response = await fetch(
         `https://jsonplaceholder.typicode.com/users/${id}`,
         { method: "PATCH" }
       );
       // JSONPlaceholder always succeeds; swap the URL for a 500 endpoint to test rollback
       if (!response.ok) throw new Error(`Renaming failed (${response.status})`);
       return response.json();
     },
     onMutate: async ({ id }) => {
       await queryClient.cancelQueries({ queryKey: ["users"] });
       const previousUsers = queryClient.getQueryData<User[]>(["users"]);
       queryClient.setQueryData<User[]>(["users"], (old) =>
         old?.map((user) =>
           user.id === id ? { ...user, name: `${user.name} (optimistic)` } : user
         )
       );
       return { previousUsers };
     },
     onError: (_error, _vars, context) => {
       if (context?.previousUsers) {
         queryClient.setQueryData(["users"], context.previousUsers);
       }
     },
     onSettled: () =>
       queryClient.invalidateQueries({ queryKey: ["users"] }),
   });
   ```

2. Attach the mutation to a "Rename" button per row and run the dev server:
   ```bash
   npm run dev
   ```

**Verify:** Click **Rename** — the row updates instantly (optimistic), and after the server responds the name snaps back to the canonical value (invalidate + refetch). Now test rollback: temporarily change the `mutationFn` URL to `https://jsonplaceholder.typicode.com/status/500` (a guaranteed failure), click again, and watch the name revert to its previous value automatically. Then restore the working URL.
