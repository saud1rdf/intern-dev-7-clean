# React High-Performance State Architecture



## Overview & The Why (لماذا هذا المفهوم حيوي؟)

React’s virtual DOM paradigm simplifies interface code by automatically computing view shifts based on state modifications. 



However, in large-scale systems (like dashboards tracking real-time telemetry inputs), unoptimized state patterns lead to sluggish rendering and unstable codebases:

1. **Cascading Re-Renders**: Storing massive, unseparated arrays inside high-level Context engines triggers full tree rebuilds across hundreds of components whenever a single attribute updates.

2. **Lost Navigation States**: Relying exclusively on temporary client-side memory resets filters, tables, and pagination states whenever a user refreshes their browser. This breaks sharing capability.

3. **Stale Closure Closures**: Incorrect setup of Hook dependency arrays causes variables to retain outdated scopes, producing subtle, hard-to-track bugs.



---



## Key Concepts (المفاهيم الأساسية)



- **Reconciliation Optimization**: Controlling render trees selectively using tools like memoization, stable references, and proper memo boundaries.

- **State Taxonomy Boundaries**: Isolating state into: Local UI State (isolated within a component), Shared Global State (cross-component panels), Server State (cached API data), and URL State (persistent coordinates).

- **Split Context Pattern**: Splitting a Context Provider into separate State and Dispatch context arrays to completely prevent unnecessary component re-renders.

- **Immutability Principle**: Ensuring React state is never mutated directly, as React relies on reference changes to trigger reconciliation safely.

## Production-Grade Code (الشيفرة البرمجية الإنتاجية)



### 1. High-Performance Split Context Pattern (`providers/UnifiedStateProvider.tsx`)

This pattern separates state context values from the dispatch context. This ensures that components only reading static states do not re-render when write handlers fire:



```tsx

'use client';



import React, { createContext, useContext, useReducer } from 'react';



interface AppState {

  theme: 'light' | 'dark';

  sidebarOpen: boolean;

}



type Action =

  | { type: 'TOGGLE_THEME' }

  | { type: 'SET_SIDEBAR'; payload: boolean };



const initialState: AppState = {

  theme: 'light',

  sidebarOpen: false,

};



// 1. Create separate contexts to isolate state from dispatcher triggers

const StateContext = createContext<AppState | undefined>(undefined);

const DispatchContext = createContext<React.Dispatch<Action> | undefined>(undefined);



function stateReducer(state: AppState, action: Action): AppState {

  switch (action.type) {

    case 'TOGGLE_THEME':

      return { ...state, theme: state.theme === 'light' ? 'dark' : 'light' };

    case 'SET_SIDEBAR':

      return { ...state, sidebarOpen: action.payload };

    default:

      return state;

  }

}



export function UnifiedStateProvider({ children }: { children: React.ReactNode }) {

  const [state, dispatch] = useReducer(stateReducer, initialState);



  return (

    <StateContext.Provider value={state}>

      <DispatchContext.Provider value={dispatch}>

        {children}

      </DispatchContext.Provider>

    </StateContext.Provider>

  );

}



// 2. Export isolated hooks with boundaries

export function useAppState() {

  const context = useContext(StateContext);

  if (!context) {

    throw new Error('useAppState must be used within UnifiedStateProvider');

  }

  return context;

}



export function useAppDispatch() {

  const context = useContext(DispatchContext);

  if (!context) {

    throw new Error('useAppDispatch must be used within UnifiedStateProvider');

  }

  return context;

}

2. High-Fidelity URL-bound Search parameters Hook (hooks/useURLQueryState.ts)

Encases filter variables inside browser search parameters directly, enabling instant deep-linking and layout preservation:

code

TypeScript



'use client';



import { useRouter, useSearchParams, usePathname } from 'next/navigation';

import { useCallback, useMemo } from 'react';



export function useURLQueryState<T extends string>(

  paramName: string,

  defaultValue: T

): [T, (newValue: T) => void] {

  const router = useRouter();

  const searchParams = useSearchParams();

  const pathname = usePathname();



  // Parse current coordinate safely

  const activeValue = useMemo(() => {

    return (searchParams.get(paramName) as T) || defaultValue;

  }, [searchParams, paramName, defaultValue]);



  const updateValue = useCallback((newValue: T) => {

    const params = new URLSearchParams(searchParams.toString());

    

    if (newValue === defaultValue) {

      params.delete(paramName);

    } else {

      params.set(paramName, newValue);

    }

    

    // Smooth, non-blocking history push transition

    router.push(`${pathname}?${params.toString()}`, { scroll: false });

  }, [router, searchParams, pathname, paramName, defaultValue]);



  return [activeValue, updateValue];

}

Best Practices (أفضل الممارسات التقنية)

	1	Never Mutate States Directly: Mutating objects directly (e.g. state.items.push(x)) breaks reference comparison. Always configure states in React using immutable copies like [...state.items, x].

	2	Keep States as Low as Possible: Store state data only at the lowest common ancestor of the components that depend on it, instead of pushing everything to top providers.

	3	Memoize Context Values strictly: Wrap composite context values in useMemo to prevent rendering drops in down-tree child components.
