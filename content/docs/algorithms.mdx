Many developers rely exclusively on built-in methods—`.sort()`, `.filter()`, `.find()`—and for most day-to-day work this is appropriate. However, understanding what occurs beneath these abstractions becomes critical when systems encounter scale, latency constraints, or novel constraints.

## Complexity Analysis: The Language of Efficiency

Big-O notation provides a standardized vocabulary for describing how an algorithm's resource consumption grows relative to input size. It abstracts away hardware differences, constant factors, and lower-order terms to focus on the dominant growth characteristic.

### Time Complexity Reference

| Complexity | Classification | Representative Operation | Practical Limit (~1s) |
|------------|---------------|-------------------------|-----------------------|
| O(1) | Constant | Hash map lookup, array index access | Unbounded |
| O(log n) | Logarithmic | Binary search, balanced BST lookup | ~10¹⁸ elements |
| O(n) | Linear | Single-pass array scan | ~10⁸ elements |
| O(n log n) | Linearithmic | MergeSort, QuickSort (average) | ~10⁶–10⁷ elements |
| O(n²) | Quadratic | Nested iteration, BubbleSort | ~10⁴ elements |
| O(n³) | Cubic | Triple-nested loops, Floyd-Warshall | ~10²–10³ elements |
| O(2ⁿ) | Exponential | Subset enumeration, naive Fibonacci | ~20–25 elements |
| O(n!) | Factorial | Permutation generation, brute-force TSP | ~10–11 elements |

### Space Complexity

Space complexity measures the auxiliary memory an algorithm requires beyond its input.

- **Auxiliary space** — Extra memory allocated excluding the input itself
- **In-place algorithms** — Require O(1) auxiliary space (e.g., QuickSort with in-place partitioning)
- **Tail-call optimization** — Certain languages optimize tail-recursive calls to O(1) stack space

### Analyzing Code: Worked Examples

```typescript
/** O(n²) — quadratic. Nested loops; doubling input quadruples the work. */
function hasDuplicateNaive(items: number[]): boolean {
  for (let i = 0; i < items.length; i++) {
    for (let j = i + 1; j < items.length; j++) {
      if (items[i] === items[j]) return true;
    }
  }
  return false;
}

/** O(n) — linear with O(n) auxiliary space. A Set makes membership O(1). */
function hasDuplicateOptimal(items: number[]): boolean {
  const seen = new Set<number>();
  for (const item of items) {
    if (seen.has(item)) return true;
    seen.add(item);
  }
  return false;
}
```

**Key takeaway:** The same operation (finding a duplicate) can be O(n²) or O(n), depending on the data structure chosen. Algorithmic awareness directly determines performance characteristics.

## Sorting Algorithms

Sorting is one of the most studied problems in computer science. The choice of algorithm affects raw performance, cache behavior, stability, and memory consumption.

### MergeSort — Guaranteed O(n log n), Stable

MergeSort divides the array in half recursively, sorts each half, and merges the results. It guarantees O(n log n) performance regardless of input distribution and preserves the relative order of equal elements (stability).

```typescript
function merge<T>(
  left: T[],
  right: T[],
  compareFn: (a: T, b: T) => number = (a, b) => (a < b ? -1 : a > b ? 1 : 0),
): T[] {
  const result: T[] = [];
  let i = 0;
  let j = 0;
  while (i < left.length && j < right.length) {
    result.push(compareFn(left[i], right[j]) <= 0 ? left[i++] : right[j++]);
  }
  while (i < left.length) result.push(left[i++]);
  while (j < right.length) result.push(right[j++]);
  return result;
}

/** MergeSort. Time: O(n log n) always. Space: O(n) auxiliary. Stable. */
function mergeSort<T>(items: T[], compareFn?: (a: T, b: T) => number): T[] {
  if (items.length <= 1) return items;
  const mid = Math.floor(items.length / 2);
  return merge(mergeSort(items.slice(0, mid), compareFn), mergeSort(items.slice(mid), compareFn), compareFn);
}
```

### When to Use Each

| Algorithm | Best For | Avoid When |
|-----------|----------|------------|
| **MergeSort** | Stable sort required, linked lists, external sorting | Memory is constrained |
| **QuickSort** | General-purpose in-memory array sorting | Worst-case guarantees are critical |
| **InsertionSort** | Small arrays (n < 50), nearly sorted data | Large random datasets |
| **Built-in `.sort()`** | Production code (engines use TimSort) | You need fully documented sort behavior |

> **Production note:** In TypeScript/JavaScript, always prefer `Array.prototype.sort()` in production. V8 and other engines implement TimSort, a hybrid of MergeSort and InsertionSort optimized for real-world data. MergeSort and QuickSort (implemented hands-on in [Task 1](#task-1-implement-and-benchmark-sorting-algorithms)) serve educational and interview purposes.

## Searching Algorithms

### Binary Search — O(log n) Lookups on Sorted Data

Binary search halves the search space with each comparison. A 1,000,000-element array requires at most ~20 comparisons.

```typescript
/**
 * Classic binary search. Returns the index of `target` or -1.
 * Time: O(log n), Space: O(1). Requires a sorted array.
 */
function binarySearch(sorted: number[], target: number): number {
  let left = 0;
  let right = sorted.length - 1;
  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2); // Avoids integer overflow
    if (sorted[mid] === target) return mid;
    if (sorted[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}
```

**Common pitfalls:** (1) Off-by-one errors — use consistent boundary conventions; (2) overflow — compute `mid` as `left + Math.floor((right - left) / 2)`, never `(left + right) / 2`; (3) unsorted input — binary search requires sorted data.

**Boundary variant:** The `lowerBound`/`upperBound` pattern (finding first/last occurrence) is covered hands-on in [Task 2](#task-2-binary-search-on-a-real-problem).

## Dynamic Programming

Dynamic programming (DP) breaks a problem into overlapping subproblems, solves each once, and stores the results. It applies when a problem exhibits **optimal substructure** (the optimal solution contains optimal subproblem solutions) and **overlapping subproblems** (the same subproblems recur).

```typescript
/**
 * Fibonacci — memoization (top-down). Time: O(n), Space: O(n).
 * Naive recursion is O(2^n) because it recomputes the same values
 * exponentially many times; a cache eliminates that waste.
 */
function fibonacciMemoized(n: number): number {
  const memo = new Map<number, number>();
  function fib(k: number): number {
    if (k <= 1) return k;
    if (memo.has(k)) return memo.get(k)!;
    const result = fib(k - 1) + fib(k - 2);
    memo.set(k, result);
    return result;
  }
  return fib(n);
}

/**
 * Minimum coins to make `amount`, or -1 if impossible (tabulation, bottom-up).
 * Time: O(amount × coins.length), Space: O(amount)
 * coinChange([1, 5, 10, 25], 30) → 2 (25 + 5)
 */
function coinChange(coins: number[], amount: number): number {
  const dp = new Array<number>(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let i = 1; i <= amount; i++) {
    for (const coin of coins) {
      if (coin <= i && dp[i - coin] + 1 < dp[i]) {
        dp[i] = dp[i - coin] + 1;
      }
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

## Graph Algorithms

Graphs model relationships between entities — social networks, road maps, dependency chains, and organizational hierarchies. The adjacency list below uses O(V + E) space versus O(V²) for a matrix, making it the default for sparse graphs.

```typescript
type Graph = Map<string, string[]>;

function buildGraph(edges: [string, string][]): Graph {
  const graph: Graph = new Map();
  for (const [from, to] of edges) {
    if (!graph.has(from)) graph.set(from, []);
    if (!graph.has(to)) graph.set(to, []);
    graph.get(from)!.push(to);
    graph.get(to)!.push(from); // Remove for directed graphs
  }
  return graph;
}

/** BFS traversal from `start`, returning the visit order.
 *  Time: O(V + E), Space: O(V).
 *  Note: array.shift() is O(n); swap in a proper queue in hot paths. */
function bfs(graph: Graph, start: string): string[] {
  const visited = new Set<string>([start]);
  const queue: string[] = [start];
  const order: string[] = [];
  while (queue.length > 0) {
    const vertex = queue.shift()!;
    order.push(vertex);
    for (const neighbor of graph.get(vertex) ?? []) {
      if (!visited.has(neighbor)) {
        visited.add(neighbor);
        queue.push(neighbor);
      }
    }
  }
  return order;
}
```

Because BFS visits vertices in increasing hop order, it yields the shortest path in unweighted graphs: track a distance alongside each queued vertex and return the distance of the first visit to the target.

**Depth-First Search (DFS)** explores as far as possible along each branch before backtracking, using an explicit stack or recursion. It is the natural choice for cycle detection, topological sorting (see [Task 4](#task-4-build-a-dependency-resolver-with-topological-sort)), and exhaustive state exploration.

```typescript
/** Partitions items[low..high] around a pivot; returns the pivot's index. */
function partition(items: number[], low: number, high: number): number {
  const mid = Math.floor((low + high) / 2); // Median-of-three pivot selection
  if (items[low] > items[mid]) [items[low], items[mid]] = [items[mid], items[low]];
  if (items[low] > items[high]) [items[low], items[high]] = [items[high], items[low]];
  if (items[mid] > items[high]) [items[mid], items[high]] = [items[high], items[mid]];
  [items[mid], items[high - 1]] = [items[high - 1], items[mid]];
  const pivot = items[high - 1];
  let i = low;
  let j = high - 1;
  while (true) {
    do { i++; } while (items[i] < pivot);
    do { j--; } while (items[j] > pivot);
    if (i >= j) break;
    [items[i], items[j]] = [items[j], items[i]];
  }
  [items[i], items[high - 1]] = [items[high - 1], items[i]];
  return i;
}

/** QuickSort (median-of-three). Time: O(n log n) avg, O(n²) worst. Not stable. */
function quickSort(items: number[], low = 0, high = items.length - 1): void {
  if (low >= high) return;
  // Two-element base case: partition() requires at least 3 elements
  // to place the median-of-three pivot at high - 1.
  if (high - low === 1) {
    if (items[low] > items[high]) [items[low], items[high]] = [items[high], items[low]];
    return;
  }
  const pivotIndex = partition(items, low, high);
  quickSort(items, low, pivotIndex - 1);
  quickSort(items, pivotIndex + 1, high);
}
```

```typescript
function searchRange(nums: number[], target: number): [number, number] {
  function lowerBound(): number {
    let left = 0, right = nums.length;
    while (left < right) {
      const mid = left + Math.floor((right - left) / 2);
      if (nums[mid] < target) left = mid + 1;
      else right = mid;
    }
    return left;
  }
  function upperBound(): number {
    let left = 0, right = nums.length;
    while (left < right) {
      const mid = left + Math.floor((right - left) / 2);
      if (nums[mid] <= target) left = mid + 1;
      else right = mid;
    }
    return left;
  }
  const start = lowerBound();
  const end = upperBound();
  return start === end ? [-1, -1] : [start, end - 1];
}

console.log(searchRange([5, 7, 7, 8, 8, 10], 6)); // [-1, -1]

```

### Task 3: Build an LRU Cache

**Objective:** Implement a production-quality LRU cache with O(1) `get` and `put` using a hash map combined with a doubly linked list.

1. Create the file: `touch src/algorithms/lru-cache.ts`

2. Implement the cache:

```typescript
class LRUNode<K, V> {
  constructor(
    public key: K,
    public value: V,
    public prev: LRUNode<K, V> | null = null,
    public next: LRUNode<K, V> | null = null,
  ) {}
}

class LRUCache<K, V> {
  private map = new Map<K, LRUNode<K, V>>();
  private head: LRUNode<K, V>;
  private tail: LRUNode<K, V>;

  constructor(private capacity: number) {
    this.head = new LRUNode(null as K, null as V); // Sentinel nodes remove edge cases
    this.tail = new LRUNode(null as K, null as V);
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  get(key: K): V | undefined {
    const node = this.map.get(key);
    if (!node) return undefined;
    this.moveToFront(node);
    return node.value;
  }

  put(key: K, value: V): void {
    if (this.map.has(key)) {
      const existing = this.map.get(key)!;
      existing.value = value;
      this.moveToFront(existing);
      return;
    }
    if (this.map.size >= this.capacity) this.evict();
    const node = new LRUNode(key, value);
    this.map.set(key, node);
    this.addToFront(node);
  }

  private moveToFront(node: LRUNode<K, V>): void {
    this.remove(node);
    this.addToFront(node);
  }
  private addToFront(node: LRUNode<K, V>): void {
    node.prev = this.head;
    node.next = this.head.next;
    this.head.next!.prev = node;
    this.head.next = node;
  }
  private remove(node: LRUNode<K, V>): void {
    node.prev!.next = node.next;
    node.next!.prev = node.prev;
  }
  private evict(): void {
    const lru = this.tail.prev!;
    this.remove(lru);
    this.map.delete(lru.key);
  }
}

const cache = new LRUCache<string, object>(3);
cache.put("user:1", { name: "Alice" });
cache.put("user:2", { name: "Bob" });
cache.put("user:3", { name: "Charlie" });
cache.get("user:1"); // moved to front
cache.put("user:4", { name: "Diana" }); // evicts user:2
console.log(cache.get("user:2")); // undefined — confirm eviction
```

```typescript
/** Topological sort via DFS post-order. Time: O(V + E), Space: O(V). */
function topologicalSort(graph: Map<string, string[]>): string[] {
  const WHITE = 0, GRAY = 1, BLACK = 2; // unvisited / in progress / done
  const color = new Map<string, number>();
  for (const node of graph.keys()) color.set(node, WHITE);

  const result: string[] = [];
  function dfs(node: string): void {
    color.set(node, GRAY);
    for (const neighbor of graph.get(node) ?? []) {
      const c = color.get(neighbor) ?? WHITE;
      if (c === GRAY) throw new Error(`Cycle detected: ${node} → ${neighbor}`);
      if (c === WHITE) dfs(neighbor);
    }
    color.set(node, BLACK);
    result.unshift(node); // prepend for topological order
  }

  for (const node of graph.keys()) {
    if (color.get(node) === WHITE) dfs(node);
  }
  return result;
}

const buildOrder = new Map<string, string[]>([
  ["app.js", ["utils.js", "config.js"]],
  ["utils.js", ["helpers.js"]],
  ["config.js", ["env.js"]],
  ["helpers.js", []],
  ["env.js", []],
]);
console.log("Build order:", topologicalSort(buildOrder));
// → ["app.js", "config.js", "env.js", "utils.js", "helpers.js"]
// Every dependency appears after its dependents — a valid topological order.
```

```typescript
/** Two pointers: two numbers in a sorted array summing to `target`. O(n) time, O(1) space. */
function twoSumSorted(nums: number[], target: number): [number, number] | null {
  let left = 0;
  let right = nums.length - 1;
  while (left < right) {
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;
    else right--;
  }
  return null;
}

/** Sliding window: max sum of any contiguous subarray of size k. O(n) time, O(1) space. */
function maxSubarraySum(nums: number[], k: number): number {
  if (nums.length < k) throw new Error("Array length must be >= k");
  let windowSum = 0;
  for (let i = 0; i < k; i++) windowSum += nums[i];
  let maxSum = windowSum;
  for (let i = k; i < nums.length; i++) {
    windowSum += nums[i] - nums[i - k]; // add entering, drop leaving
    maxSum = Math.max(maxSum, windowSum);
  }
  return maxSum;
}

console.log(twoSumSorted([2, 7, 11, 15], 9)); // [0, 1]
console.log(maxSubarraySum([1, 4, 2, 10, 23, 3, 1, 0, 20], 4)); // 39
```

### Task 6: Union-Find for Connected Components

**Objective:** Implement Union-Find with path compression and union by rank, then count connected components in an undirected graph.

1. Create the file: `touch src/algorithms/union-find.ts`

2. Implement the data structure:

```typescript
class UnionFind {
  private parent: number[];
  private rank: number[];
  private components: number;

  constructor(n: number) {
    this.parent = Array.from({ length: n }, (_, i) => i);
    this.rank = new Array<number>(n).fill(0);
    this.components = n;
  }

  /** Find with path compression: flattens trees for near-O(1) queries. */
  find(x: number): number {
    if (this.parent[x] !== x) this.parent[x] = this.find(this.parent[x]);
    return this.parent[x];
  }

  /** Union by rank: attach the smaller tree under the larger one. */
  union(x: number, y: number): boolean {
    const rootX = this.find(x);
    const rootY = this.find(y);
    if (rootX === rootY) return false;
    if (this.rank[rootX] < this.rank[rootY]) {
      this.parent[rootX] = rootY;
    } else if (this.rank[rootX] > this.rank[rootY]) {
      this.parent[rootY] = rootX;
    } else {
      this.parent[rootY] = rootX;
      this.rank[rootX]++;
    }
    this.components--;
    return true;
  }

  getComponentCount(): number {
    return this.components;
  }
}

function countComponents(n: number, edges: [number, number][]): number {
  const uf = new UnionFind(n);
  for (const [u, v] of edges) uf.union(u, v);
  return uf.getComponentCount();
}

console.log(countComponents(5, [[0, 1], [1, 2], [3, 4]])); // 2
console.log(countComponents(5, [[0, 1], [1, 2], [2, 3], [3, 4]])); // 1
```

3. Run locally: `npx tsx src/algorithms/union-find.ts`
