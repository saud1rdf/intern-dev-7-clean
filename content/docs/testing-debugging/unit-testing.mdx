# Unit, E2E Testing & Structured Logging

## Overview

Testing and monitoring are essential parts of reliable software systems.

Testing verifies that features work correctly before deployment, while logging and observability help developers understand problems after deployment.

Common production problems include:

1. Bugs caused by untested code changes.
2. UI regressions across different pages.
3. Difficult debugging without structured logs.

---

# Key Concepts

## Unit Testing

Unit tests verify small isolated pieces of code.

Examples:

- Functions.
- Business logic.
- Data transformations.

Tools:

- Jest.
- Vitest.

Tools:

Structured Logging

Production applications should use structured logs instead of random console messages.

Example:

import pino from "pino";


export const logger = pino({

  level: "info",

  base: {

    service:
      "user-onboarding",

    environment:
      process.env.NODE_ENV,

  },

});


export function createLogger(
  traceId:string
){

  return logger.child({

    traceId,

  });

}
Jest Unit Testing Example

Example business function:

export function calculateTotal(
  price:number,
  tax:number
){

  if(price < 0){

    throw new Error(
      "Invalid price"
    );

  }


  return price + (price * tax);

}

Test:

describe(
  "calculateTotal",
  ()=>{


    it(
      "calculates final price",
      ()=>{


        const result =
          calculateTotal(
            100,
            0.15
          );


        expect(result)
          .toBe(115);


      }
    );


    it(
      "rejects negative prices",
      ()=>{


        expect(
          ()=>calculateTotal(
            -10,
            0.1
          )
        )
        .toThrow(
          "Invalid price"
        );


      }
    );


  }
);
Playwright E2E Example
import {
  test,
  expect
} from "@playwright/test";


test(
  "user login flow",
  async ({page})=>{


    await page.goto(
      "/login"
    );


    await page
      .getByLabel("Email")
      .fill(
        "user@example.com"
      );


    await page
      .getByRole(
        "button",
        {
          name:"Login"
        }
      )
      .click();


    await page.waitForURL(
      "/dashboard"
    );


    await expect(
      page
    )
    .toHaveTitle(
      /Dashboard/
    );


  }
);
Testing Best Practices
Query by Accessibility Roles

Prefer:

getByRole("button")

because it tests accessibility and user behavior.

Do Not Hide Errors

Always log errors with enough information for debugging.

Clear Mocks Between Tests

Example:

afterEach(()=>{

  jest.clearAllMocks();

});

This prevents tests from affecting each other.
