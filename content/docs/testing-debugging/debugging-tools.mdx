## Introduction

Debugging is the process of identifying, isolating, and fixing bugs in software. Effective debugging is a critical skill for developers, enabling you to quickly diagnose and resolve issues in your code. Modern development provides powerful debugging tools ranging from browser developer tools to Node.js debuggers and comprehensive error tracking services.

Understanding debugging tools and techniques is essential because bugs are inevitable in software development. The ability to quickly identify the root cause of a problem, rather than guessing or randomly modifying code, dramatically improves productivity and code quality. This document covers the essential debugging tools and techniques for web and Node.js development.

## When to Use Debugging Tools

Different debugging approaches are appropriate for different scenarios.

### Browser-Based Debugging

For issues that appear in the browser, such as rendering problems, JavaScript errors, or network request failures, browser DevTools provide the most direct access to what's happening.

### Node.js Debugging

Server-side issues, API problems, and performance bottlenecks are best debugged using Node.js debugging tools and logging.

### Complex State Issues

When bugs involve complex state interactions, debugging tools that allow you to pause execution and inspect variables are invaluable.

### Production Issues

For bugs that only occur in production, error tracking services and log aggregation tools help identify issues without direct access to the running environment.

### Error Handling and Logging

```typescript
// Structured error handling
class ApiError extends Error {
  constructor(
    message: string,
    public statusCode: number,
    public code: string,
    public details?: any
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

async function fetchData<T>(url: string): Promise<T> {
  try {
    const response = await fetch(url);
    
    if (!response.ok) {
      throw new ApiError(
        `Request failed with status ${response.status}`,
        response.status,
        'REQUEST_FAILED',
        { url, status: response.status }
      );
    }
    
    return response.json();
  } catch (error) {
    if (error instanceof ApiError) {
      throw error;
    }
    
    if (error instanceof TypeError && error.message.includes('fetch')) {
      throw new ApiError(
        'Network error',
        0,
        'NETWORK_ERROR'
      );
    }
    
    throw new ApiError(
      'Unknown error',
      0,
      'UNKNOWN_ERROR',
      { originalError: error }
    );
  }
}

// Logger with different levels
enum LogLevel {
  DEBUG = 0,
  INFO = 1,
  WARN = 2,
  ERROR = 3,
}

class Logger {
  private level: LogLevel;
  
  constructor(level: LogLevel = LogLevel.INFO) {
    this.level = level;
  }
  
  private log(level: LogLevel, message: string, meta?: any) {
    if (level < this.level) return;
    
    const timestamp = new Date().toISOString();
    const logObject = {
      timestamp,
      level: LogLevel[level],
      message,
      ...meta,
    };
    
    if (level >= LogLevel.ERROR) {
      console.error(JSON.stringify(logObject));
    } else if (level >= LogLevel.WARN) {
      console.warn(JSON.stringify(logObject));
    } else {
      console.log(JSON.stringify(logObject));
    }
  }
  
  debug(message: string, meta?: any) {
    this.log(LogLevel.DEBUG, message, meta);
  }
  
  info(message: string, meta?: any) {
    this.log(LogLevel.INFO, message, meta);
  }
  
  warn(message: string, meta?: any) {
    this.log(LogLevel.WARN, message, meta);
  }
  
  error(message: string, meta?: any) {
    this.log(LogLevel.ERROR, message, meta);
  }
}

const logger = new Logger(LogLevel.DEBUG);

logger.info('User logged in', { userId: 123 });
logger.warn('Rate limit approaching', { remaining: 10 });
logger.error('API request failed', { url, statusCode: 500 });
```

### Production Error Tracking

```typescript
// Sentry integration
import * as Sentry from '@sentry/nextjs';

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  environment: process.env.NODE_ENV,
  tracesSampleRate: 0.1,
  
  beforeSend(event, hint) {
    // Filter out known non-actionable errors
    const error = hint.originalException;
    if (error instanceof NetworkError) {
      return null; // Don't send network errors
    }
    return event;
  },
  
  initialScope: {
    tags: {
      component: 'checkout',
    },
  },
});

// Wrap pages with error boundary
import { ErrorBoundary } from '@sentry/react';

function App() {
  return (
    <ErrorBoundary
      fallback={({ error, resetError }) => (
        <ErrorPage 
          error={error} 
          onRetry={() => resetError()} 
        />
      )}
    >
      <MainApp />
    </ErrorBoundary>
  );
}

// Manual error capture
try {

} catch (error) {
  Sentry.captureException(error, {
    level: 'error',
    extra: {
      context: 'checkout-flow',
      step: 'payment-processing',
    },
  });
  throw error;
}
```

## Common Mistakes

### Not Reproducing the Issue

```javascript
// ❌ WRONG - Guessing without reproducing
// "I think the issue might be..."
// Makes random changes hoping to fix

// ✅ CORRECT - Reproduce first
// 1. Get exact steps to reproduce
// 2. Create minimal test case
// 3. Verify fix actually resolves issue
```

### Not Using Source Control

```javascript
// ❌ WRONG - Making random changes
// "Let me try changing this..." -> "That didn't work" -> "Let me try this..."
// No way to track what was tried

// ✅ CORRECT - Use version control
// 1. Create a branch for debugging
// 2. Make one change at a time
// 3. Document what you tried
// 4. Easy to revert failed attempts
```

### Not Checking the Simplest Explanation

```javascript
// ❌ WRONG - Assuming complex cause
// "The issue must be a race condition in the state manager"
// "Maybe it's a memory leak in the component"

// ✅ CORRECT - Check simple things first
// 1. Is the API returning correct data?
// 2. Are all dependencies loaded?
// 3. Is there a typo in variable name?
// 4. Is the code even being executed?
```
