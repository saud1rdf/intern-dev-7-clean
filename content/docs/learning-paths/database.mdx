## What Is a Database in an API?

In the FastAPI path, your tasks lived in a Python dictionary:

```python
tasks: dict[int, Task] = {}
```

This works for learning, but when you stop the server the data disappears. A database stores the data on disk. The next time the server starts, the tasks are still there.

You will use **SQLite** in this path. SQLite is a file-based database. You do not need to install a separate database server. The same code works with PostgreSQL later — you only change the connection string.

## How This Learning Path Works

4. Copy the full working code and understand every part.

## The Concepts You Will Learn

| Concept | Plain-language meaning | Why it matters |
|---------|------------------------|----------------|
| **Database** | A file or server that stores data permanently | Data survives restarts |
| **Table** | A structure that holds rows of the same type (like a spreadsheet) | Your tasks become rows in a table |
| **ORM** | A library that lets you use Python classes instead of writing SQL | You write `session.add(task)` instead of raw SQL |
| **Session** | A temporary connection to the database for one request | You get one, use it, then close it |
| **Primary key** | A unique number that identifies one row | The `id` field |
| **Migration** | A controlled way to change the database structure later | Not covered here, but you will need it in real projects |

## The Three Most Common Libraries

| Library | Best for | Learning curve | Notes |
|---------|----------|----------------|-------|
| **SQLAlchemy** | Most production projects | Medium–High | Industry standard. Used by many companies. |
| **SQLModel** | FastAPI projects | Low | Made by the FastAPI author. Uses SQLAlchemy underneath. |
| **Tortoise ORM** | Async-first apps | Low–Medium | Inspired by Django. Clean async syntax. |

You will implement the guided project with **SQLModel**. The other two are shown with working examples so you can switch later if needed.

## Guided Project: Add a Database to the Task Management API

You will take the Task Management API from the FastAPI path and make the tasks permanent.

### Step 1 — Install the library

From your project folder (with the virtual environment activated):

```bash
pip install sqlmodel
```

**What this does:** installs SQLModel and its dependency SQLAlchemy.

### Step 2 — Create the database connection

Create a new file called `database.py`:

```python
from sqlmodel import SQLModel, create_engine, Session

sqlite_file_name = "tasks.db"
sqlite_url = f"sqlite:///{sqlite_file_name}"

engine = create_engine(
    sqlite_url,
    connect_args={"check_same_thread": False}
)

def create_db_and_tables():
    SQLModel.metadata.create_all(engine)

def get_session():
    with Session(engine) as session:
        yield session
```

**What each part does:**

- `sqlite_url` tells SQLModel to use a file named `tasks.db` in the current folder.
- `create_engine` creates the connection.
- `create_db_and_tables` creates the tables the first time you run the app.
- `get_session` gives each request its own database session and closes it automatically.

**Why this way:** this is the pattern shown in the official SQLModel + FastAPI tutorial. You will see the same pattern in most FastAPI database examples.

### Step 3 — Define the Task model

Open `main.py` and replace the old in-memory models with this:

```python
from typing import Optional
from sqlmodel import SQLModel, Field

class Task(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    title: str
    description: Optional[str] = None
    completed: bool = False
```

**What this does:**

- `table=True` tells SQLModel this class is also a database table.
- `id` is the primary key. It is optional on create because the database assigns it.
- The other fields are the same as before.

One class now handles both validation (like Pydantic) and database storage.

### Step 4 — Full working code

Replace the contents of `main.py` with this complete version:

```python
from typing import Optional
from fastapi import FastAPI, Depends, HTTPException
from sqlmodel import Session, select
from database import create_db_and_tables, get_session
from sqlmodel import SQLModel, Field

app = FastAPI(title="Task Manager API with Database")

class Task(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    title: str
    description: Optional[str] = None
    completed: bool = False

@app.on_event("startup")
def on_startup():
    create_db_and_tables()

@app.post("/tasks/")
def create_task(task: Task, session: Session = Depends(get_session)):
    session.add(task)
    session.commit()
    session.refresh(task)
    return task

@app.get("/tasks/")
def list_tasks(session: Session = Depends(get_session)):
    statement = select(Task)
    tasks = session.exec(statement).all()
    return tasks

@app.get("/tasks/{task_id}")
def get_task(task_id: int, session: Session = Depends(get_session)):
    task = session.get(Task, task_id)
    if not task:
        raise HTTPException(status_code=404, detail="Task not found")
    return task

@app.put("/tasks/{task_id}")
def update_task(task_id: int, task_update: Task, session: Session = Depends(get_session)):
    task = session.get(Task, task_id)
    if not task:
        raise HTTPException(status_code=404, detail="Task not found")
    task.title = task_update.title
    task.description = task_update.description
    task.completed = task_update.completed
    session.add(task)
    session.commit()
    session.refresh(task)
    return task

@app.delete("/tasks/{task_id}")
def delete_task(task_id: int, session: Session = Depends(get_session)):
    task = session.get(Task, task_id)
    if not task:
        raise HTTPException(status_code=404, detail="Task not found")
    session.delete(task)
    session.commit()
    return {"ok": True}
```

**What each endpoint does:**

- `create_task`: adds the task to the session, commits (saves) it, then refreshes so the `id` is filled in.
- `list_tasks`: runs a `select` and returns all rows.
- `get_task`: looks up one task by id. Returns 404 if missing.
- `update_task`: loads the existing task, changes the fields, then saves.
- `delete_task`: deletes the row and commits.

**What you would change for another project:** the model fields and the path names (`/tasks/`). The session pattern stays the same.

### Step 5 — Run and test

```bash
uvicorn main:app --reload
```

Open `http://127.0.0.1:8000/docs`. Create a task. Stop the server with Ctrl+C and start it again. The task is still there.

You should also see a new file called `tasks.db` in your project folder. That file is the database.

## Other Libraries

### SQLAlchemy (classic style)

If you prefer the library most companies use, here is the same Task model with SQLAlchemy:

```python
from sqlalchemy import create_engine, Column, Integer, String, Boolean
from sqlalchemy.orm import declarative_base, sessionmaker

Base = declarative_base()
engine = create_engine("sqlite:///./tasks.db", connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine)

class Task(Base):
    __tablename__ = "tasks"
    id = Column(Integer, primary_key=True, index=True)
    title = Column(String, index=True)
    description = Column(String, nullable=True)
    completed = Column(Boolean, default=False)

Base.metadata.create_all(bind=engine)
```

Docs: https://docs.sqlalchemy.org/en/20/orm/quickstart.html

### Tortoise ORM (async)

If your project is fully async, Tortoise is a common choice:

```python
from tortoise import fields
from tortoise.models import Model
from tortoise.contrib.fastapi import register_tortoise

class Task(Model):
    id = fields.IntField(pk=True)
    title = fields.CharField(max_length=120)
    description = fields.TextField(null=True)
    completed = fields.BooleanField(default=False)

    class Meta:
        table = "tasks"
```

Then register it with FastAPI:

```python
register_tortoise(
    app,
    db_url="sqlite://tasks.db",
    modules={"models": ["main"]},
    generate_schemas=True,
    add_exception_handlers=True,
)
```

Docs: https://tortoise.github.io/getting_started.html

## Common Mistakes and How to Avoid Them

| Mistake | What happens | Fix |
|---------|--------------|-----|
| Forgetting `create_db_and_tables()` | No tables are created | Call it on startup |
| Not using `Depends(get_session)` | Session errors or data not saved | Always inject the session |
| Forgetting `session.commit()` | Changes disappear | Commit after add/delete |
| Using one global session | Requests interfere with each other | Create a new session per request |
| Editing the model without deleting `tasks.db` | Old table structure remains | Delete the `.db` file while learning |

## Beyond This Learning Path

When you are ready to use PostgreSQL (the same database from the Docker path), change only the connection string:

```python
postgres_url = "postgresql://user:password@localhost/tasks"
engine = create_engine(postgres_url)
```

Everything else stays the same. This is why learning the pattern once is enough.
